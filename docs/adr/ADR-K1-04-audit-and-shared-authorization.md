## 0. 范围与边界

本 ADR 定义模块工具调用的最小内核审计、审计保留/查看/导出边界，以及 UI 与 Agent 发起业务操作时共用的身份、资源和授权权威。审计只记足以关联调用和说明结果的元数据，不记正文、凭据、完整提示或完整工具参数。模块自己的日志不是 Agent24 内核审计。

依赖 C1 K-2 的 `append_audit` 字段白名单/黑名单方案。本 ADR 不修改代码、不新增法律、不定义业务模块日志或审计 UI 版式，也不将既有审批、审计链或模块日志宣称为本 ADR 已实现。K1-7 才实现审计与共同授权接缝，并接入 #708 端到端验收。

## 2. 决策

### 2.1 每次模块工具调用都形成可关联的内核审计

对 K1 模块工具每次尝试，审计必须能关联以下元数据：

- 稳定 `run_id`、`tool_call_id`、模块 ID、操作 ID；session 可用时记录不透明 session 引用。
- 发起 actor 的内核身份引用，以及授权决定引用；actor 身份由宿主确定，不能接受模型/模块自报值。
- 有限结果类别/结果码（成功、失败、拒绝；超时、取消和结果未知可用闭集子类）、发生时间；可选记录受限时长/尺寸元数据。
- 必要时的资源引用只能使用经过授权且不暴露内容的标识/摘要；不得以审计记录保存完整请求、响应或资源快照。

`run_id + tool_call_id + module_id + operation_id` 与 ADR-K1-01 的关联要求一致。调用成功、工具/宿主失败、审批拒绝、政策拒绝、超时、取消及结果未知均须有终态记录；宿主应在派发前确保有可写审计能力，无法建立关联记录时不派发。若进程中断导致没有终态，预派发记录须能显示未完成/结果未知，不得伪报成功或失败。审计写入错误不得被静默吞掉；对已发生但无法补记的结果，系统须暴露审计降级状态，不自动重试可能有副作用的调用。

记录中不得出现正文、凭据、密钥、完整提示、完整工具输入/输出、任意错误 message、模型自由文本理由或可还原这些数据的片段。拒绝原因只允许来自闭集结果码；尺寸/时长只作元数据。字段和值约束由 C1 K-2 白名单/黑名单共同执行；调用者不得通过 `detail` 任意塞入 JSON。

### 2.2 复用现有哈希链字段，不把哈希当授权或防篡改的外部证明

模块审计沿用 `agent24-store` 现有字段语义：`seq`、`ts`、`actor`、`action`、`detail`、`prev_hash`、`hash`；使用现有 SHA-256 链接/验证逻辑，`detail` 只容纳 K-2 批准的元数据 schema。调用事件 action 使用内核保留命名空间，并以调用关联 ID 连接预派发与终态事件。

哈希链完整性不是访问控制、actor 真实性、不可否认性或远程备份。链缺失、校验失败或无法追加时，审计视图明确显示完整性/可用性问题；不得显示为“已验证”。模块日志、普通 tracing 和业务表都不能替代内核哈希链记录。

审计记录保留 180 天，与计划中决策日志的保留期限一致；到期后自动过期，用户查看/导出仅覆盖当前保留窗口。清理不能直接删掉中间链项后仍声称全链从 genesis 可验证。K1-7/K-2 实现须定义并验证可过期的链段/检查点边界，使保留窗口可校验、过期项不可再读且清理后链状态可检测；现有 `verify_audit_chain` 从 genesis 遍历全表，尚不具备此语义。不得为方便清理而延长调用元数据到 180 天以外的可读保留。

### 2.3 用户可查看、导出内核审计

宿主提供用户可访问的查看和导出入口，返回 180 天窗口内经过字段白名单过滤的内核审计记录及其完整性状态。导出包含最小关联元数据和链验证/检查点信息，不包括正文、凭据、完整提示、完整参数或模块自有日志。查看与导出本身经宿主身份与访问控制；模块不能读取全局审计表或代用户导出。

本 ADR 固定“可查看、可导出”和 180 天保留，不规定具体产品页面、文件格式或逐条人工删除入口。不得让普通模块操作删除/修改审计记录；法定删除或用户权利若要求更改此边界，须单独审议其与哈希验证、备份和保留要求的冲突。

### 2.4 UI 与 Agent 共用同一身份、资源及业务操作权威

每个业务操作只定义一份内核权威的 actor/主体解析、资源范围校验、动作许可、策略评估和执行服务。UI 和 Agent 是不同的发起界面/调用适配器，二者必须调用同一业务操作入口和同一授权决策；UI 不能凭“用户点了按钮”绕过该操作的资源/组织/来源策略，Agent 也不能借模型身份扩大用户权限。

宿主把可信的用户/主体身份、操作来源（UI 或 Agent）、Agent run/tool-call 关联（适用时）和授权决定注入上下文。UI 直接发起的操作没有 run 时仍使用同一用户身份与相同资源/动作规则，并在审计中标为 UI 来源；Agent 发起的操作保留相同主体并增加 run/tool-call 关联。身份缺失、主体不一致、资源不可验证、策略不可用或任一入口试图改写身份时拒绝执行。持久操作的校验、提交和审计应由共同服务串行/原子化，不能由 UI 和 Agent 分别复制业务校验。

内核审计记录业务操作的主体/调用关联、动作标识、资源引用摘要、授权引用和结果码。业务服务可以保有领域审计，但它不得替代内核审计，也不能由模块自定义日志声称为用户/Agent 已获授权的证明。共同入口不要求所有 UI 操作都伪造 Agent run 或触发与 Agent 相同的交互式确认；具体确认形式可以因入口不同，但其身份、资源和策略权威必须一致，并且任何更严格规则继续生效。

### 2.5 依赖、拒绝和失败路径

K1-7 实现依赖 C1 K-2 字段约束落地或有可验证的等价白名单门；依赖 ADR-K1-01 的稳定调用关联字段、ADR-K1-03 的宿主授权引用，以及 K1-5/6 提供的模块调用和授权上下文。依赖未满足、字段 schema 未知、审计服务不可用、哈希校验失败、用户身份/资源不确定时均 fail closed：不派发新工具调用、不执行未提交的业务动作，并返回有限的拒绝/不可用结果。不得通过模块本地日志、UI 侧判断或 tracing fallback 放行。

## 3. 威胁模型

本 ADR 保护调用者身份与用户资料的机密性、授权和资源边界、审计记录的完整关联，以及 UI/Agent 业务操作行为的一致性。信任边界包括模型可控参数、第三方/第一方模块、模块错误消息、UI renderer、REST 客户端、审计字段调用方和本地数据库操作者。

- 模块/模型试图将提示或资料写入 `detail`、错误消息或日志：K-2 闭集字段和值约束与此 ADR 的禁止字段共同拒绝；不能只依赖调用者自律。
- UI 与 Agent 对同一资源应用不同权限：一个共享内核业务操作服务解析身份、校验资源/动作并执行，适配器不各自实施授权。
- 调用伪造 actor、run 或资源，或复制关联 ID：宿主注入主体和关联；ID 仅用于审计关联，不是授权凭据/业务幂等键。
- 删除/篡改审计行或审计存储不可用：校验可检测链断裂；预派发审计门和明确降级态避免无记录地派发。哈希链不能抵御有权改写整库并重算链的本地攻击者，除非未来引入链外锚定。
- 通过模块自有日志冒充内核审计：模块无权写内核链、读取完整审计库或决定其结果状态。

## 4. 兼容性、迁移与保留

1. 现有 `audit_log` 通用调用者逐步迁移到经 K-2 约束的 schema；未批准的自由文本/未知字段不能进入新 K1 审计记录。旧记录不因此自动变成合规模块审计。
2. K1 工具的审计关联字段须与 ADR-K1-01 一致；不得把 `tool_call_id` 用作业务幂等键，也不得自动重试以补审计。
3. 现有审批记录、模块日志和通用风险审计继续服务其现有用途；只有 K1-7 打通调用终态、共同授权服务、查看/导出、180 天生命周期及验收后，才可声明本 ADR 的能力完成。
4. 180 天窗口的清理/链段检查点须覆盖重启、并发追加、窗口边界验证、导出和清理中断。实现前不得删除现有链记录来模拟达到保留期。
5. 此 ADR 为 Proposed。K1 高风险实现 task 仍须先写反例测试并证明旧行为失败，门禁通过并获 PR-Daemon APPROVE 后再合入；ADR 本身不授权实现。

## 5. 反例测试清单（K1-7 实现必须先写并证明修复前失败）

以下是后续实现验收，不是本 ADR PR 已运行的行为测试：

1. 成功、失败、拒绝、超时、取消和结果未知各完成一次模块调用 → 可用同一调用关联查询到受限结果事件；模块退出导致没有终态时显示未完成/结果未知。
2. 通过工具参数、错误 message、模块响应和 prompt 注入正文、凭据、完整提示或任意 JSON 字段 → 不进入 `detail`、导出或模块可见审计；K-2 未知字段拒绝。
3. 伪造 actor、session、run/tool-call ID、授权引用或跨调用复制 ID → 记录的主体由宿主确定，不能藉关联 ID 获得权限或业务去重。
4. UI 与 Agent 对相同主体、资源、动作执行操作 → 使用同一授权决策/资源校验；UI 直调不能绕过来源/组织限制；Agent 不得改变主体。
5. 审计 pre-dispatch 追加失败、schema 未知或链验证失败 → 工具不派发、业务副作用不提交，并返回可观察的拒绝/不可用；不得只打印日志后继续。
6. 终态审计写失败或进程崩溃 → 不伪报“审计完整”，不自动重做副作用；预派发事件保留未完成/结果未知状态。
7. 并发 append、重启、链项篡改、链段过期边界、过期清理中断 → 保留窗口验证检测缺口/篡改，不因清理静默断链；不得声称超过 180 天仍可读取已过期事件。
8. 用户查看/导出时 → 仅导出当前保留窗口、授权允许的元数据和链完整性状态；不能导出正文、凭据、提示、完整参数或模块自有日志。
9. 模块自行记录“成功”、UI 自行记录“已批准”或模块本地日志可用 → 均不能替代内核审计，也不能使被拒绝的共同授权入口执行成功。

## 7. K1-7 实现切片建议（每片 ≤300 行）

每片独立 PR、base `ab/kernel`；涉及审计/授权均为高风险，逐片跑反例及门禁并等 PR-Daemon APPROVE 后合入。若单片必须跨模块超过 300 行，先拆成 fail-closed 可合入的小片。

1. **7.1 K-2 对接与类型化审计事件**：确认 `append_audit` 允许字段/拒绝字段和闭集 action/result code；为 K1 引入受限 metadata 类型与预派发/终态事件。拒绝任意 detail、自由文本和正文的测试先失败后修。
2. **7.2 模块工具调用接线**：由内核注入 actor、run/session/tool-call/module/operation 和授权引用；预派发记录成功后才 dispatch，所有终态追加结果；测试成功、失败、拒绝、超时、取消、审计不可用和进程中断。
3. **7.3 UI/Agent 共同业务授权入口**：先选一个消费者操作建立共用内核服务；UI/Agent 适配器都传递宿主主体与来源，由服务统一校验资源、动作和策略并负责提交/审计。不要在本片顺手实现 Documenting 领域 API 或 UI 重做。
4. **7.4 保留、链段与检查点**：实现 180 天过期、链段/检查点验证、并发/崩溃安全清理；升级 `verify_audit_chain` 语义并验证过期记录不可读、剩余窗口完整性可查。不能通过直接删除中间行让旧验证器失效。
5. **7.5 用户查看/导出与 #708 E2E**：提供受宿主身份保护的查看/导出路径，只暴露允许字段和链校验状态；用真实产品路径证明 UI/Agent 共用授权、三类调用结果审计、正文不落审计、180 天生命周期。证据按组件、接线、验收和发行分别记录。
