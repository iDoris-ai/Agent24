# ADR-MEMORY-P1：个人记忆生命周期与清除权

> **PROPOSED / 待外审接受，2026-10-26 修订（原 DRAFT 2026-10-23）。** 第 9 节五项已由产品负责人 jason 于 2026-10-26 拍板。本修订在精确 head 上被 clestons APPROVE，即作为 adr-s9 的外审接受记录。接受的是设计与首版范围，不批准任何迁移或生产实现；PLAN 各行的格式外审和实现门不变。P1-01 仅获授权编写设计；本文不是已批准法律、迁移或生产实现许可。基线 `f16e65a95f9732f4e00cb288f967e40e0978eb7b`；本轮只读源码与给定报告，没有读取真实记忆库、执行清除或重跑探针。下文“应/必须”均是拟议验收要求，须外部设计批准后实施。

## 1. 权威、问题与决策范围

遵循 [MEMORY 法律](../laws/MEMORY.md)、[APPROVAL 法律](../laws/APPROVAL.md)、[当前 OpenAPI](../../protocol/openapi.yaml) 与实现；产品方向来自 [MEMORY-STRATEGY §4.2](../research/MEMORY-STRATEGY.md)。策略有草案与历史状态，不能覆盖已发布契约。已核对现有 ADR/计划：未发现同义的已批准生命周期/purge ADR；[旧来源草稿](../agent/PLAN-M1-SNAPSHOT-PROVENANCE.md) 仅归档，不能当本 ADR 或迁移批准。执行依赖见 [P1 计划](../agent/PLAN-MEMORY-P1.md)。

Agent24 主线是“用户输入 → 上下文/召回 → 模型 → 工具审批/执行 → 持久化 → 系统回执 → 管理与恢复”。P1 在此链上增加个人控制；外部文档、知识、媒体、语音和模型服务只通过内核契约协同，不另建记忆权限权威。M1/P0 #720 已经用户真机验收、M2 #767 已发布、H01 #1024 已完成，不重开。

证据输入：2026-10-22 Downloads 台账三稿、2026-10-23 readiness 探针/模块证据、独立复核（持久引用与状态见计划 §1）。探针报告证明 H02 新 evidence 重记后重试 Conflict/真实 chat 方法 Failed；P02 完整 marker 输入/普通历史在 provider 副本误裁，持久原文未删；P01 pause/恢复绿；P03 已补真实 HTTP 五项观察和协调者独立复跑，首 provider barrier 在收到请求后，未证明首次发送前屏障。独立复核允许设计启动，不等于本方案 APPROVE。

**建议核心决定：正常生命周期内 no-loss；仅用户明确确认的 purge 是破坏性例外。** 压缩、归档、配额、暂停、更正、撤回均不能偷偷删原文。写入失败必须报告未保存，不能以“聊天继续”伪称 no-loss 已兑现；拟议恢复语义与旧承诺的变化需单独评审。

## 2. 用户操作契约

| 操作 | 新行为与读取 | 原文、历史和恢复 | 回执要表达的事实 |
|---|---|---|---|
| 暂停 pause（已有） | 停止新开始 run 的记忆写入与跨 session recall；不等于停聊天日志 | assertion/原始对话保留；按 `putMemorySettings`，既有审批恢复在通过来源核对后使用已存 snapshot，不按新开关重决定；来源无法证明时，#1197 在 `drive_resume` 中以 `source_unproven` 拒绝恢复（`agent24-agent/src/lib.rs`）；真实撤回重校验仍独立生效 | “已暂停记忆；历史保留；已开始的审批在来源可证明时按原快照恢复，否则不恢复” |
| 撤回 retract（已有） | assertion 不再作为当前有效记忆召回；真实 host recall 的请求副本需按当前契约裁剪 | 原文、审计与旧版本保留；再次明确 remember 可重申，不能靠清审计绕 H02 | “不再用于当前记忆召回；原始对话仍保留” |
| 更正 supersede（拟议） | 用户选择旧断言并提交新值，建立修订链；当前召回用有效新值；冲突可并存并标来源 | 旧值仍可按 valid-time/recorded-time 查询；未知有效日期留空，不能用写入时间伪造；purge 后 as-of 也不可返回旧正文 | “已更正；旧版本保留”；F11 `asserted_by` 来自可信身份 |
| 清除 purge（拟议） | 按确认的目标闭包封锁后清除受控正文及派生物；所有查询/重建/恢复受 tombstone 约束 | 不可撤销；不自动清掉同一用户的所有文档/模块；全个人范围或指定会话范围须分别预览 | 逐副本显示已清除/处理中/失败/不受控；逻辑阻断不冒充清理完成 |
| 无痕 incognito（拟议） | 从入口选择独立临时会话，默认不读既有个人记忆、不写长期记忆或历史 | 内存上下文可用；结束/崩溃不恢复；不是事后 purge，不把已持久普通会话改名为无痕 | “本机会话内容不持久保存；发送目的地及工具副作用另列” |

purge 不等同于撤回；暂停不等同于无痕；更正不等同于物理覆盖。已发往模型或工具的请求不能追回。P03 尚不足以证明每次 provider/fallback 都做实时撤回检查，不能写成现有保证；新的 purge 屏障要求见 §5。

## 4. 身份、范围与确认

P1 只做本人个人域。当前 daemon 使用 `LOCAL_USER` 加组织/分区目录注入 owner，是本地单用户实现，不冒充多用户认证。拟议个人管理端点通过宿主可信会话认证和逐操作授权推导 owner；模型、REST body 的 owner/space/run selector、模块请求均不是授权。沿用 L-MEM-1..3，模块不能拿底层句柄或全局维护接口；不借 purge 改 K1/APPROVAL 已批准规则。

建议首版只提供“选定会话及其来源依赖闭包”和“本人全部个人记忆”两档，不做任意关键词删句。预览必须列事实/历史/派生物/Run/附件/托管备份计数、对其他记录影响、未知与外部副本；共享来源会扩到整条记录时必须显示并再次确认。无可信绑定的旧数据使相关范围停在需处理状态，不能猜测归属；范围外用户资料不删除。

确认由可信 UI/CLI 的独立用户动作完成，绑定 actor、scope、预览版本、目标 ID 集合/截止世代、一次性 nonce 和短期有效期；不得让模型自然语言、工具整会话授权或模块自行确认代替。点“永久清除”前可先导出但不强制制造新副本；提示导出包也含原文。确认提交时重验身份/范围/世代，范围变更返回冲突重新预览；不接受陈旧预览扩大删除。实际 endpoint/schema/TTL 留后续 wire 评审，不在此指定迁移号。

最小审计保留操作 ID、可信 actor 的不透明标识、范围类型、删除世代、阶段、数量、错误码和时间；不保存原文、摘要、自然语言删除理由、路径标题或可字典猜测的内容 hash。必要 tombstone 用稳定随机对象 ID/数据集 ID/世代，和可见审计分开授权；已有内容派生 ID 须采用受密钥保护的匹配表示或改用映射，不能直接泄露。保留成本、密钥丢失与数据集退休规则列入 §9 待决项。

## 5. 事务、后台任务、取消与恢复

建议采用“持久意图 + 每库原子批次 + 幂等后台清理”，不声称跨 SQLite 文件、文件系统与模块有一个 ACID 事务。状态为 `preview → prepared → fenced → cleaning → verified`；错误停在 `blocked/partial` 并保留 fence；仅 `preview/prepared` 可 `cancelled`。`verified` 表示声明的受控清单全部验过，另附不受控副本，不表示全球无残留。控制存储内必须以单次原子 CAS 实现 `prepared→fenced` 与 `prepared→cancelled` 的互斥转换；哪个先持久提交即胜出。fence 记录提交前不得启动删除，提交后崩溃按 fenced 恢复并拒绝取消；跨库批次不能把未落盘的内存标志当取消边界。

1. **prepare**：认证/确认后在独立恢复控制存储持久化意图、冻结的目标清单、删除世代和幂等键，再进入任何破坏性步骤。意图本身不含正文；失败时不删除。控制存储不随旧业务备份覆盖，写满/不可用则拒绝 purge 与相关恢复。
2. **fence**：在新请求/导出/归档/重建/后台任务/审批恢复入口检查未完成意图，将目标范围隔离。关闭旧写入者和源自目标的派生任务，等待其退出或隔离；旧读事务也须结束。启动时先处理意图再开放服务；跨库 fence 中途崩溃仍由控制存储阻止重新开放。
3. **删除批次**：同一库的正文/关联/索引更新和任务进度在短事务中提交；采用引用安全顺序，目录迁移仍遵守 L-MEM-5/6，不将 purge 伪装成 re-key。文件用受控规范路径/句柄验证 owner 与引用，unlink 成功但记进度前崩溃可安全重试；不存在按已处理验证。模块调用使用同一操作 ID，绝不跨网络 await 持 SQLite 写锁。
4. **并发屏障**：后台作业绑定来源 ID 与删除世代，提交前 CAS 重验；旧世代写入拒绝。恢复、导出、索引构建先读 fence，发布结果前再验；预览后的新数据不悄悄加入本次范围。受影响 run 不允许继续从旧 snapshot 执行工具或发送模型；不能精确裁出的混合内容按整个 run 隔离。未知旧 snapshot 保留但停止续跑，提供新建会话指引。
5. **发送边界**：fence 与宿主发送许可线性化；fence 后不得新授权目标内容发送，provider/fallback 都走该许可。已取得许可的在途发送记为不可追回，取消仅尽力；等待清退后才确认受控读取已封锁，不能承诺远端没收到。具体接缝待 P03 契约外审，不能用“检查后再 await”掩盖窗口。
6. **verify**：逐落点验证正文/引用/投影不可读、旧任务不能提交、重开与 rebuild 无复活，登记各副本结果。仅所有声明的受控副本完成才给“受控范围已清除”；模块离线/格式未知/磁盘失败显示 partial，保持阻断，支持重试而非成功绿勾。

同 actor+幂等键+相同规范请求返回同一 job/结果；相同键不同范围拒绝，超时重试不能创建第二个删除任务。确认后首次 fence 提交是取消分界：此前 CAS 取消意图并证明无破坏发生；此后“停止等待/暂停清理”不撤销 tombstone、不恢复数据，后台可重试直到收敛。每个阶段注入进程死亡，重启由 durable intent 重建进度；请求取消和任务完成竞争以持久状态为准。

清除的是已确认对象/修订及来源闭包，不是永久禁止出现同样文字。范围清理验证后，用户在新会话主动再次输入可形成新身份/新世代；不能沿用被清除对象 ID，不能把旧包/后台重放伪装成新输入来解禁。实现前需与当前内容派生 assertion ID 的幂等规则一起设计；此新生命周期不能用 H02 最小 bugfix 偷带。活跃进程的摘要、provider 请求副本、UI/事件缓冲也要失效或清退，不能仅查磁盘断言不可读。

## 6. 归档、导出与备份恢复防复活

恢复门的权威不能只存在于会被旧备份替换的 `memory.db`。建议新增与业务备份分离的恢复控制存储，记录数据集 ID、单调删除世代、意图与 tombstone；备份/归档 manifest 写入格式版本、数据集 ID、覆盖世代和完整性凭证。恢复必须向可信控制存储取得最新水位，校验身份和清单完整性，先导入隔离区、应用 tombstone/未完成意图并验证，再开放任何 query、rebuild、工具恢复或导出。

本机“独立文件”并不防整机回滚。跨机恢复须携带经校验的最新删除清单和可信水位；若只有旧包、控制存储缺失/回滚/版本未知或不能证明水位最新，**拒绝作为原数据集开放**，保留隔离并提示恢复控制凭证。不能由“用户继续”静默绕过防复活；全机与控制凭证一起回滚超出本地单机可独立证明范围，必须在回执中明确。独立保存方式与信任锚是外审阻塞决策，未解决前不上线恢复承诺。

导入保留来源稳定 ID、撤回/更正状态及删除世代，不能换 ID 绕过 tombstone；格式不认识、缺引用、跨 owner 或重复冲突则拒绝/隔离，同一包重试幂等。新机器 owner 由认证主体重绑定，不能采信包内任意 owner；经证明属于本人数据集才可映射。JSON 为可恢复权威，Markdown 为可读投影；包校验和只证明完整性，不证明身份或水位新鲜。建议可恢复导出默认加密，密钥与包分离；明文 Markdown 需明确选择和受控落点说明，密钥遗失不可承诺可恢复。

冷归档只在新包已落盘、校验和与可回放验证成功后切换引用；旧在线副本的回收不得先于此点。共享 blob 必须以受权引用计数确认最后一个引用才回收；默认仅 owner 内去重。托管旧备份可删除或重写，无法改写的包撤销开放资格并标待物理清理；不得因此给物理完成回执。未授权的外部原始文件、离线设备或用户自存包不擅自访问/删除。

## 7. 无痕与可兑现边界

无痕必须在收第一条正文之前选定存储策略：EventLog、Run/thread/snapshot、工具参数与结果、trace、摘要、附件、桌面历史、日志/诊断正文均不写持久介质；使用内存存储与最小非内容指标，不能先落盘后等会话结束删除。审批可在内存等候但不承诺冷恢复，重启后不给“恢复无痕会话”。自动 remember/导出/跨 session recall 关闭；切回普通模式只开新会话，不静默追记。

首版建议默认禁用会写持久副本的模块、文件工具和未经声明的 provider。用户另行允许外发或文件副作用时，提前单独展示目的地/产物保留范围；不能再宣称该产物无痕。模型既有本地缓存、swap、崩溃转储、操作系统快照、远端模型缓存与日志均不能由应用保证取证级擦除；loopback 也不是不留副本证明。只有端到端受控路径验收后才展示“本机会话内容不持久保存”，否则入口不可启用此承诺。

P1 承诺限 Agent24 控制的逻辑数据、已登记可清理的本地文件与协同副本。不会承诺删除失控旧备份、用户复制的明文、远端已收请求/模型训练或缓存；外部服务删除请求仅按实际回执报告。不存在“全网彻底删除”按钮文案，亦不宣称 GDPR 就绪。物理介质取证级清除、法律保全、组织管理员代删和共享空间归属留后续独立治理设计。

## 8. 威胁模型与验证门

| 威胁 / 故障 | 机制与必须证明的反例 |
|---|---|
| 模型/模块伪造 owner、scope、确认；marker 冒充宿主 | 服务端身份注入、独立确认；拒跨 owner/陈旧 nonce；host provenance 与内容形状分离，用户同文仍保真 |
| 旧包/旧任务/旧审批让内容复活 | 数据集水位、fence、提交 CAS、启动恢复门；缺 tombstone/回滚水位/旧 generation 均拒开放 |
| 多副本只删一份、摘要泄漏、共享 blob 误删别人 | 来源依赖闭包、逐落点结果、owner 内去重；删主账本但保留 FTS/Run/旧版本的变异必须使验收失败 |
| 断电、满盘、权限错误、模块失联、超时重试 | 每阶段 crash 注入、持久进度与幂等；失败保持 partial，不回滚成可读；清理意图可独立持久化 |
| 本机管理员任意改 DB/替换所有控制凭证、恶意外部模型保存 | 不在本地应用可证明边界；检测到缺失/不一致 fail-closed，不把 hash 或 localhost 解释成完整安全隔离 |

验收使用合成双 owner 数据，经真实 daemon/API/provider spy/磁盘重开验证；默认绿测试不能替代显式红测。覆盖 pause 与 purge 差异、更正 as-of、JSON 恢复、引用混合与离线副本、每步崩溃/取消、满配额执行 purge、备份回滚与缺控制库、无痕异常退出和工具失败；实际发布另做 jason 真机链。P02 同进程/冷恢复 marker history 已补红证，P03 HTTP/资格变化/no-session 已补观察；H02 固定时钟同秒重申的审计 ID 碰撞已由 #1152（merge 7dd6f08f）修复，见 `agent24-memory/src/writer.rs` 的避碰写入（`commit_with_audit_using_clock`，测试 `h02_reassert_skips_occupied_suffix_without_reusing_events`）；仍须补完整同文三来源修复矩阵和新发送屏障验证。旧观察测试不证明拟议 purge 屏障已实现。

## 9. 高影响决策（jason 2026-10-26 已决）

以下五项已由产品负责人 jason 于 2026-10-26 拍板。本节在外审 APPROVE 后才算被接受；接受的是设计与首版范围，不批准迁移或生产实现。每项的“放开”只指相关计划行可以开始格式或设计工作，各行自身的格式外审和实现门不变。

**① 清除粒度（已决）。** 决定：purge 首版只做“全个人域”。归属无法证明时拒绝执行。按会话删除延后。原因：当前 `SessionHistory` 分类没有历史源对象边，证明不了会话闭包（`rust/crates/agent24-store/src/message_origin.rs`）。放开：P1-02c、P1-04/05/06 的格式设计、P1-08 全域设计。仍挡住：按会话删除。风险：全域删除粒度粗，用户想删一段对话时只能删全部；预览必须明示这一点。

**② 恢复信任锚（已决）。** 决定：恢复前用独立、在线、单调的锚验证数据没被回滚。验证失败则拒绝恢复。首版不退休 tombstone。放开：P1-04b 导回、P1-05c/d、P1-08c。没有锚就延期离线恢复。风险：`0001_initial` 的 `audit_log` 哈希链（`prev_hash`/`hash`）与业务数据同在一个库里，可以随整库一起回滚，所以不能当锚（`rust/crates/agent24-store/migrations/0001_initial.sql`）。

**③ 加密（已决）。** 决定：恢复包默认认证加密，密钥与包分开保存（macOS 钥匙串）。密钥丢失则不可恢复。明文导出必须用户单独选择。放开：P1-05a/b 与 P1-04b 格式。风险：包加密不保护 tombstone 里可猜的内容 ID。`agent24-agent/src/retain.rs` 的 `persist` 用 `checksum(owner ‖ object)` 生成 ID，知道正文候选的人可以离线验证猜测。

**④ 在途与外部副本（已决）。** 决定：fence 之后不再授予新的发送或工具许可。已授权在途的尽力取消。受控但失联的副本保持 `partial`。失控副本单独列出。不承诺“全部清除”。放开：P1-05 并发与 P1-08→09 的设计。风险：模型路由 fallback 复用同一请求（`agent24-models/src/router.rs`，按 route 循环调用 `provider.complete(req, …)`），循环前检查不足以提供发送线性化。

**⑤ 无痕首版（已决）。** 决定：零工具、零模块，只允许一个经过全落点验收的本地 provider。验收前入口禁用。放开：只放开 P1-09 的最小路径。风险：普通 run 路径会持久写 snapshot（`append_snapshot_run_messages`，`agent24-agent/src/lib.rs`），无痕不能复用普通运行路径。

来源方案已落地：消息来源由独立表 `run_message_origins`（migration 0021、0022，#1168/#1195）承载，K1 `run_source_tags` 只管隐私/路由，二者正交，见 [ADR-MEMORY-RECALL-MESSAGE-ORIGINS](ADR-MEMORY-RECALL-MESSAGE-ORIGINS.md)。生命周期变更、purge/无痕/迁移/导入格式均须各自精确版本外审；本 ADR 获接受也不替代实现 PR 门禁。
