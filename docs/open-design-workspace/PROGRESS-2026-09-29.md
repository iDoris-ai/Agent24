## M2 — Minimal `agent24 acp`

Prototype happy path 优先：initialize → session/new → session/prompt → stream → terminal result。

### M2.1 — ACP happy-path contract audit

- [x] Open Design 现有 `acp-json-rpc` engine 已证明最小握手顺序：`initialize` → `session/new` → `session/prompt`；不需要 Agent24 新写 OD parser/engine。
- [x] `initialize` 最小成功结果可为 `{protocolVersion: 1}`；`session/new` 最小成功结果为 `{sessionId}`（models 可选）。
- [x] `session/prompt` 输入为 `{sessionId,prompt:[...]}`；Prototype 先消费 `type=text` 内容，resource/image/tool-rich payload 后续增强。
- [x] 流式文本采用现成 ACP notification：`session/update` + `{sessionId,update:{sessionUpdate:"agent_message_chunk",content:{text}}}`。
- [x] Agent24 已有完整可复用数据面：daemon discovery/bearer、`POST /api/v1/sessions`、`POST /api/v1/runs`、`GET /api/v1/events` WebSocket，以及 typed `model.delta` / `run.completed` / `run.failed` / `run.cancelled`。
- [x] 冻结映射：ACP session = 一个 Agent24 Session；prompt 前先连 WS 避免事件 race；POST Run 后按 run_id 过滤事件；`model.delta` → message chunk；completed → `stopReason=end_turn` + token usage；failed/cancelled → JSON-RPC failure。
- [x] Prototype auth 暂时复用现有 legacy daemon discovery host bearer；capability-scoped Creative token 留到 M5/M6，不阻塞 M4。

M2.1 状态：**DONE**。
