## M6.1 — WorkspaceHandle authority foundation

两次独立 read-only audit 都同意 **不要先给 ToolContext 增加一个可空的 workspace 字段**：当前 normal dispatch、restored approval、explorer/subagent/self-wake 等路径会手工重建 `ToolContext`，此时提前加入 `Option<WorkspaceHandle>` 容易形成 silent `None` downgrade。也不能只把现有 `ResolvedHostWorkspaceRoot` 改成 `pub`；它仍保存 `canonical_root`，且没有 active Run lease / stale-handle 语义。

因此按小步纪律拆成两个连续 PR：

- **M6.1a — atomic run authority snapshot（IN PROGRESS）**：从 #567 `87b7630` 新开 store-only slice；在一个 read transaction 内验证 bound Run、完整 kind=`run` lease history、唯一且未释放的 supplied lease、active `orchestrator_scratch` workspace、current generation、committed allocation 与 root identity，返回后续 handle minting 所需的不可伪造 snapshot。无 ToolContext / fs / shell / approval / ACP / Open Design 改动，目标 <300 changed lines。
- **M6.1b — opaque pinned WorkspaceHandle（NEXT）**：`agent24-workspace` 以 M6.1a snapshot exact-pin root，pin 后 revalidate authority，再返回无 public constructor / serde / canonical-root getter 的 process-local handle。非 Unix 平台在真实 pinned-root primitive 落地前继续 fail closed。
