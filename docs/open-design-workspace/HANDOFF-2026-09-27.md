N5–N9 都保持 `run()` inert；不得把这些测试和 dormant seams 宣称为可用 helper runtime。N10 才允许设计并接入 production host loop，且必须区分：

- `Phase::Empty` 只表示 target owner tree 已确认空，不等于 host session 完成；正常 tombstone 仍须服务 `Signal` / `IsEmpty`，直到 parent EOF。
- parent EOF、fatal transport、broken output 或显式 cancel 发生后，host 只能在 cleanup 到 confirmed Empty 后结束。
- first-launch rejection 的 `PreOwnedCleanup` 与 accepted generation 的 `GenerationHarness` 必须保持单一 cleanup authority，不能因错误返回提前 drop owner。

N10 已经完成两份独立设计审计，冻结为四个依赖切片：

1. N10a 只补 `ParentEof` / `Failed` 会话结束事实及传播，`run()` 保持 inert；
2. N10b 增加拒绝启动 cleanup harness 与同步 host loop，所有错误都继续持有 owner 到 confirmed Empty；
3. N10c 才接真实 stdio 与 `run()`，并增加基础三平台 binary smoke；
4. N10d 覆盖异常输出、parent EOF 与 descendant 的真实 binary 验收。

正常 `Empty` 不结束 session；正常 parent EOF 还要等待已接受的 Reply / Exit flush。fatal transport、output failure、Ready timeout 或显式 cancellation 则在 confirmed Empty 后退出，不得等待已失效的 writer。生产 stdio 必须 clone 成独立的 owned、non-inheritable handle，不能让 detached writer 持有全局 stdout lock。
