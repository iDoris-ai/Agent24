### 3.2 #519：实现 native generation assembly

本轮继续在 #517 之上创建 #519：

- PR #519 `feat/sidecar-native-generation-owner`
- final head `6f82db0`
- 383 additions / 4 deletions，4 files
- 新增 crate-private `NativeGeneration`

核心行为：

- 接受真实 `OwnedLaunch`
- stdout 只移动一次到 generation-local `ReadyReadWorker`
- stderr 只移动一次到 generation-local `StderrDrainWorker`
- host `ControlWorker` / `OutputWorker` 继续以 borrowed lifetime 使用
- partial assembly 失败时不发出 `Owned`
- failure object 保留同一个 authoritative process owner，可继续 force / observe / reap
- cleanup owner 用 `Box<OwnedLaunch>` 保存，关闭 Windows `result_large_err` strict-clippy blocker
- Windows stdout/stderr 继续复用现有 `into_owned_handle() -> std::fs::File` 路径，没有复制或创建第二 native reader

本轮实际发现并修复了两项 Windows 问题：

1. 初版直接把 Tokio `ChildStdout` / `ChildStderr` 传给同步 `Read` worker，Windows `cargo check` 失败。修复为 `from_native_stdout_in` / `from_native_stderr_in`，继续使用已有 native-handle 转换逻辑。
2. 修复后 Windows strict clippy 报 `NativeGenerationBuildError` 过大。将 cleanup owner Box 化后关闭该 blocker。

最终验证：

- local `cargo test -p agent24-sidecar-host`: 148 / 148 PASS
- focused native-generation tests: PASS
- strict clippy: PASS
- fmt / `git diff --check`: PASS
- Ubuntu CI: PASS
- macOS CI: PASS
- Windows check / test / strict clippy: PASS
- 两次 independent exact-head review on `6f82db0`: PASS / PASS

三平台 CI 证明当前代码可跨平台编译并通过各自测试集，但 #519 的两个 native-generation assembly 测试是 Unix-only；Windows 原生 assembly / stdio smoke 仍属于接 `run()` 前的后续门禁。

因此 #519 已达到本轮内部代码 checkpoint；剩余是 external review 与 dependency-stack merge gate。
