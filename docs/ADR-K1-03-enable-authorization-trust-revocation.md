# ADR-K1-03：启用授权、信任与撤销

**状态**：提案（2026-10-07；须经 PR-Daemon APPROVE 后方可采纳）
**范围**：Agent24 通用模块内核；Documenting 是首个消费者
**依据**：`docs/agent/PLAN-KERNEL-K1.md` §2 第 3 条、§4 K1-3；jason 2026-10-07 对 §2 五组问题的裁决

## 背景与问题

当前工具调用的审批流水线围绕一次 run 中的一次工具调用建立待审批项。它有拒绝、超时、取消、会话/目标范围 grant 等机制，但没有“启用模块时一次性确认逐工具权限，之后在已确认范围内调用”的授权记录与生命周期。Documenting 因而会把正常使用反复送进逐次审批。

另有 Creative capability 用于隔离 Open Design runtime 的 API 权限。它把调用者限制在 workspace、principal、资源和操作集合内，并支持 TTL、撤销和请求复验。这是可以复用的宿主 authority 模式与实现经验，不等同于模块工具授权，也不意味着 OD-M11 已完成或恢复。

本 ADR 决定授权原则、信任边界和与 capability 的接口。它不批准任何实现、法律修改、首发云模式承诺，也不把模块安装或签名视为用户同意。

## 决策

### 1. 授权是宿主签发的、逐工具且有边界的许可

宿主在启用/首次使用时展示模块及每项工具的实际权限摘要，至少逐工具列出：

| 展示项 | 要表达的内容 |
| --- | --- |
| 可读 | 数据类型、来源/资料范围、资源或路径边界；注明是否包含文档正文、元数据或用户提供内容。 |
| 可改 | 数据类型与作用范围、写入/删除等动作、可影响的资源；没有写权限时明确标为无。 |
| 可外发 | 可能离开设备的数据、用途、精确目的地/接收方及网络出口；没有外发权限时明确标为无。 |
| 风险 | 由宿主根据工具实现、动作和数据流定级；同时显示有效的数据政策限制。第三方 manifest、插件文案或工具返回值中的风险自报只能作为待核验描述，不能降低宿主等级或改变许可。 |

许可的身份至少绑定模块 ID 与来源、精确工具 ID/版本、权限集合、资源/数据范围、用途、目的地、用户/组织政策版本、签发者、签发时间和明确的到期时间。未列明、无法解析或未知的范围一律拒绝；不能以模块级的宽泛“信任”代替逐工具范围。

同意必须由用户在宿主控制的界面明确作出，逐项范围可读，并有拒绝/取消路径。安装、更新、导入、签名有效、首次启动或对话中的请求本身都不构成同意。没有匹配的有效授权时，阻止调用；不得回退为一次运行期 prompt 之外的隐式许可。

### 2. 数据策略及更严格限制优先

- 文档及其他敏感来源默认 `LocalOnly`。任何云处理必须由用户显式授权到**资料 × 用途 × 目的地**，并带有效期、可撤销；缺少任一维度即拒绝。
- 组织、管理员、来源本身的更严格限制优先于用户授权和普通便利开关。便利开关不能放行受限来源，模块也不能自报更宽松的数据标记。具体标签传播与 LocalOnly 出口执行由 ADR-K1-02/K1-6 定义。
- 获准云处理是可选能力，首发默认关闭；是否在首发承诺提供获准云模式另行决定。未实现或无法证明某次出口满足政策时，明确报不可用并阻断。
- **临时限制不随本 ADR 撤除**（jason 2026-10-07 裁决第 5 点）：现有「存在远端模型档位时不通告文档工具」的保守限制，只在 K1 隐私执行全部完成并验收后撤除，也就是 K1-6a（本 ADR 对应的启用时授权）**和** K1-6b（隐私标记传播与 LocalOnly 出口门）都落地并通过 #708 验收之后。K1-6a 单独落地不构成撤除条件；实现者不得以「启用授权已上线」为由放开该限制。
- 即使用户给某项工具常驻许可，每次调用仍受当前风险等级、操作范围、来源政策、目的地、组织限制和宿主总开关约束。逐次确认可以更严格，不能扩大既有许可。

### 3. 有效期、撤销和在途调用

每条许可必须有有限有效期和可检查的到期时间；过期即失效，需重新明确同意。具体产品时长不在本 ADR 中固化，但不得使用永不过期的许可。权限、模块版本、来源、目的地、用途或政策摘要变化时，旧许可不能被自动扩张。

撤销由宿主作为授权权威串行化：撤销完成后，新调用不得通过；已排队/在途调用须取消，并在不可逆副作用点和每个外发边界前复验授权。实现应等待已接受的调用进入安全终态或明确报告停止失败；不得在未完成撤销的情况下报告成功。撤销不能收回已送达远端的数据或逆转已经完成的外部副作用，界面与审计不得声称可以做到。

撤销、禁用或过期时，应使关联能力/执行代次失效并通知正在运行的调用；进程内缓存不得成为绕过。若无法可靠取消或复验，执行必须 fail closed。对于已经越过远端接收/不可逆提交点的操作，系统说明结果不可保证撤回，但禁止继续产生后续副作用。

### 4. 第一方、第三方、升级与来源信任

- 第一方模块（如 Documenting）在随产品安装后默认处于“已安装并可启用”状态。首次使用前仍须由宿主展示逐工具权限并取得一次明确确认；默认安装不是权限授予，也不降低宿主风险等级。
- 第三方模块以及开发期手动安装的模块默认视为高风险，保持未授权/不可用，直到宿主核验并由用户明确确认。手动安装不是开发者信任声明。
- 模块更新若改变任何工具权限范围、数据类型、用途、目的地、风险结果或授权解释，须暂停受影响工具并重新同意；相同范围的更新也必须重新核验来源与制品，不能只凭版本号复用旧授权。无法比较范围时按范围变化处理。
- 签名可证明制品由对应密钥签署且签名校验通过；来源校验可证明制品来自所声明的分发/注册来源；版本/摘要校验可证明运行制品与被核验制品一致。它们本身不能证明代码安全、风险自报真实、权限合理、数据处理合规、密钥持有人可信，也不能替代用户授权或运行时隔离。
- 第一方身份只影响安装来源/默认可见性，不使权限自动获批。被撤销的签名密钥、来源策略拒绝、摘要不符或验证服务不可用时，禁止启用或升级后的调用，并要求安全恢复路径。

### 5. 审计与产品记录

授权、重新同意、撤销、过期及因政策拒绝应有可查看、可导出的宿主审计记录。只记关联所需元数据（如 actor、module/tool/version、范围摘要、用途/目的地标识、策略版本、时间、结果码、关联调用 ID）；不得记录正文、凭据、完整提示或完整工具参数。保留 180 天，与决策日志一致。具体字段和存储实现留给 ADR-K1-04，不能因此延后 K1-6a 的授权/撤销闭环。

## 与 OD-M11 capability 路线的接口

本 ADR 的模块授权回答“该模块的这个工具，可否对这些数据/资源执行这个动作并送往这个目的地”；capability 路线回答“这个客户端凭什么调用哪条宿主 API、针对哪个资源”。两者是分层门禁： capability 身份不能代替模块用户同意；模块授权不能给客户端发放高权限 API token。

K1-6a 可消费宿主授权决定，按最小操作/资源/有效期签发或更新内部执行能力；每次工具调用须同时通过模块授权与下游 capability/resource 校验。撤销需使授权版本/代次失效，并通知在途调用。该映射不要求 K1 依赖 OD-M11 全线交付，也不恢复其暂停任务；OD-M11 的运行时接线仍须遵守其自身计划与门禁。

具体接口应保持以下关系：

1. 复用“宿主持有 authority、短期 scoped capability、精确资源/操作校验、撤销和过期复验”的概念，不复用 Creative 的 workspace/principal 领域模型或 bearer 作为用户同意记录。
2. 如同一进程/请求同时需要两类许可，授权结果只取交集；任一层拒绝、过期、未知或撤销即拒绝。不得因 `CreativeRuntime` capability 有效而越过模块许可、LocalOnly 或组织/来源约束。
3. capability 的 mint/revoke 仍由可信宿主控制面执行；模块/第三方不能自 mint、续期、复活或扩大 claims。普通 renderer/backend proxy 不能成为权限管理旁路。
4. OD-M11 F11.0 要求路由级 action/resource 校验和高权限接口隔离；F11.1 要求 Desktop 自己拥有 capability daemon、host bootstrap 和 fail-closed 冲突处理。K1 可以定义将来消费这些宿主接口的契约，但不修改其状态，不要求 F11.0/F11.1 先完成。

## 状态、迁移与否决路径

本 ADR 采纳后，现有逐次审批保持原行为，直到 K1-6a 有可验证的启用授权路径。迁移顺序为：宿主生成逐工具权限摘要 → 用户明确同意并记录有期限授权 → 调用时先校验授权/政策 → 仅在授权覆盖的范围内免除重复审批 → 显示和审计现有授权 → 撤销、到期、禁用或权限变化时阻止新调用并停止在途调用。未迁移的工具保持现有逐次审批或不可用，不得自动推断已同意。

对拒绝、取消、过期、摘要不一致、组织/来源限制、风险未知、签名/来源校验失败、策略服务不可用、授权存储/撤销通知失败，统一否决为拒绝或不可用。用户不得通过“始终允许”便利选项跨越上述否决。

## 反例与实现验收测试

本 PR 只写 ADR，不改执行代码，因此这些是 K1-6a/b 必须先于实现落地的反例测试；每项应先在旧行为上证明失败，再实现，再证明通过。不得把文档断言当成测试已经通过。

1. 第三方 manifest 自报 `Read`，实际工具会外发资料：宿主仍将外发按自身分析定级；无同意时调用被拒。
2. 用户只授权某份资料的某用途和某云目的地：换资料、用途或目的地即拒绝；更严组织/来源策略仍优先。
3. 文档来源默认 LocalOnly，即使远端模型已配置或模块/工具自称 local-safe，也没有外发。
4. 第一方 Documenting 已安装但首次确认未完成：不可调用；确认后授权范围内调用不再逐次审批。第三方/手动安装仍为高风险未授权。
5. 用户撤销时有一个在途调用：新调用立即拒绝，在途调用被取消或在副作用/外发前停止；已经送达的内容不被报告为已收回。
6. 授权到期或模块升级扩大任一权限范围：调用被拒，直到用户重新同意；同版本号但摘要不符也拒绝。
7. 有效签名/来源只能通过制品来源验证，不能使未授权调用成功；验证不可用时拒绝启用。
8. OS `enabled=true` 或 Creative capability 有效均不能绕过模块授权、LocalOnly 或更严组织/来源限制。

## 法律映射与后续变更

实现须遵守 [`APPROVAL.md`](laws/APPROVAL.md) L-APPR-1..7（用户权限不可由风险判断放宽；统一审批门；External 不给宽泛 session grant；常驻授权按确切目标收窄；读权限不进入存储）、[`MEMORY.md`](laws/MEMORY.md) L-MEM-1..7（身份/范围由内核注入，不让模块自报）及 [`CONTEXT.md`](laws/CONTEXT.md) L-CTX-1..4（来源可点名、可审计）。LocalOnly、授权撤销等长期隐私不变量如需成为新法律，必须另提 `docs/laws/PRIVACY.md`（或获批位置）的独立 PR；本 ADR 不代替法律流程。

本 ADR 不恢复 OD-M11 的 PAUSED 状态（`PLAN-OD-NEXT.md` F11.0/F11.1 与 [`ADR-005`](open-design-workspace/design/ADR-005-CAPABILITY-AUTHORITY.md) 仍按其原路线管理）。本 ADR 获批只为 K1-6a 提供契约，不能推断任何机制已实现或 Documenting 已验收。

## K1-6a 实现切片建议（每片 ≤300 行）

1. **6a.1 授权摘要与宿主确认**：为第一方 Documenting 与手动安装模块生成可信、逐工具权限摘要；建宿主确认/拒绝接缝和持久化许可骨架；无记录即拒绝。先覆盖“未确认不可调用”负例。
2. **6a.2 调用门与风险交集**：在工具分发处校验模块/工具版本、授权范围、宿主风险、来源/组织限制；许可精确匹配时只跳过重复审批，不跳过现有高风险或策略门。逐项反例先失败再修。
3. **6a.3 期限、变更和撤销**：到期、禁用、升级范围变化触发失效/重同意；撤销传播到排队/在途调用和副作用/外发边界，提供可观察的停止结果。复用能力撤销通知时保持模块授权与 capability 数据模型分离。
4. **6a.4 查看、导出与记录接线**：展示/导出当前许可及 180 天元数据审计；正文/凭据不入记录。若审计字段依赖 K1-04/K-2 未定契约，则留在该依赖之后，前三片仍 fail closed。

每片是独立 task PR，按 `ab/kernel` 为 base；不超过 300 行，不顺手实现 K1-6b 的隐私标记传播与 LocalOnly 出口门。涉及权限的每片均等 PR-Daemon APPROVE 后再合入。
