> pilot 的 review triage 把「真问题但不阻塞（B）」和延后项记在这里。
> 主线 task 全部完成后，由 `pilot run` 批量合成一个 cleanup PR 做掉，逐条标 [x] done=PR#n。
> `- [ ]`=OPEN，`- [x]`=DONE。GitHub PR comment 是永久兜底。
>
> **一条规则，学费是 FU-16（2026-09-02）**：
> **未做完的事必须由一条 `- [ ]` 承载，不能写在一条已关闭条目的正文里。**
> 「若将来发现 X 不足以覆盖，这条要重新打开」读起来像闸门，**实际是留言** ——
> 没有任何机制会再读它一次，`count-open` 也不会数它。
> 交付了 A 但原条目要的是 A+B 时：把原条目的范围**收窄到 A** 并标 done，
> **另开一条 `- [ ]` 承载 B**。两个数（`count-open`、`[x]` 与 `done=PR#n` 相等）
> 才会同时说真话。
>
> 判据用**宽**写法，不要加行尾锚：
> ```bash
> [ "$(grep -cE '^- \[x\] FU-' F)" = "$(grep -cE '^- \[x\] FU-.*done=PR#[0-9]+' F)" ]
> ```
> `[0-9]+` 已经排掉了正文里字面的「done=PR#n」；再加 ` *$` 只会**禁止任何尾部标注**
> （如 `done=PR#142(仅子进程支)`）并误报。在最初那个真 bug 上两种写法同样给 1 ——
> **锚从来没有承重。**（PR-Daemon 在 #144 用四棵树做控制实验推翻了它自己开的处方。）
