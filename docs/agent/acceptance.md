# Agent24 验收标准（用户视角）

## ME-4（2026-09-23，当前轮）—— 「外置 OS 能用上内核的调度和模型了」

判断依据：**我的个人 OS（Sin90）能按节律提醒我、能帮我整理复盘和分类，而这些都不需要把它编进内核。**

| 子项 | 要求 | 对应 |
|:---|:---|:---|
| Routine 真的会响 | 建「每周 3 次运动」→ 真实到点时 Sin90 收到触发并记录（同一次到点重试也只记一次）；重启 daemon 后**不会变成两条**；daemon 重启、模块慢启动都不会把它变成「已禁用」 | ME4-1.x + Sin90 M3 |
| 我暂停的就是暂停的 | 我在内核侧暂停了某条模块的定时，模块再怎么对账也不会把它重新打开 | ME4-1.2.2 |
| 外部伪造不了触发 | 经 daemon 的 HTTP 入口伪造一次「到点了」的请求（含各种编码变体），Sin90 收不到 | ME4-1.3.2 |
| 复盘数字可信 | 周复盘里「本周 X 小时」纯由事件回放得出 | Sin90 M4 |
| AI 只提建议 | AI 做的每一项改动都是一条待我批准的提议，不直接改数据 | Sin90 M5 |
| 隐私默认本地 | 不声明就只用本地模型；断网时分类照常可用 | ME4-4.x + Sin90 M5 |
| 第二个模块 | Cos72 mytask：发任务 → 完成 → 我批准后才记积分；与 Sin90 同时装互不可见 | ME4-5.3.x |
| 别人也能写 | 只看 wire 文档就能写出一个能挂上的 Node.js 模块 | ME4-5.4.1 |
| 能装 | v0.5.0 发布后，在另一台干净机器上**只用发布出来的文件**装 daemon + 两个模块，二者都显示 mounted | ME4-6.x |

**ME-4 不在范围**：Life Packs（Sin90 M6）、myshop/myvote、模块签名、进程隔离。

# Agent24 M1 验收标准（用户视角，v0.5.0 之后）

> 这是「做成了没有」的标准，不是技术任务清单（技术拆解见 [`tasks.md`](tasks.md)）。
> 判断依据只有一条：**记忆是不是真的在替我工作，且我敢让它替我记。**
> 记录日期：2026-08-23

## 一、我的对话被真的记住了

今天的真实状态：M-D 的 12 个记忆模块 **crate 外引用全为 0**，agent loop 用的还是 M-D 之前的 `CanonicalSession`，而它把会话存成 KV blob —— **情节权威里根本没有对话**。

| 子项 | 要求 | 当前状态 |
|:---|:---|:---|
| 对话进事件日志 | 一次真实对话在 EventLog 里留下按 seq 有序的完整轮次 | ⏳ T1.3.1 |
| 崩溃能恢复 | 丢掉内存态后从事件重放，上下文与崩溃前逐条相等 | ⏳ T1.3.3 |
| 长对话不炸 | 超出预算时按 token 压缩，且**摘要失败不丢消息** | ⏳ T1.3.2 |
| 只有一份压缩实现 | `CanonicalSession` 退成投影，不与 `Condenser` 并存 | ⏳ T1.3.2 |

## 二、记忆归属清楚，不会互相污染

| 子项 | 要求 | 当前状态 |
|:---|:---|:---|
| 两个领域 OS 互不可读 | 跨模块探针：A 写的东西 B 既读不到也搜不到 | ✅ F1/F8（**回归必须持续通过**） |
| 我自己的记忆模块碰不到 | agent loop 的记忆与模块分区不相交 | ✅ F8（裸 user id）→ ⏳ T1.2.1 改为 `usr:` 空间后仍成立 |
| 数据搬家不丢 | 迁移后老 key 读不到、新 key 读得到，且再跑一次移动 0 个 | ⏳ T1.2.2 |
| 归属可追溯 | 任何分区都能从目录问出它属于哪个 org / space / 谁创建 | ✅ F8 |

## 三、「能不能访问」有一个被问到的地方

| 子项 | 要求 | 当前状态 |
|:---|:---|:---|
| 判定点存在 | 句柄发放前经过 `Authorizer` | ⏳ T1.1.2 |
| 行为零变化 | 接线后既有隔离探针**全部继续通过** | ⏳ T1.1.2 |
| 拒绝是可解释的 | `Decision` 带 `reason`，能落进日志 | ⏳ T1.1.1 |
| 签名不用重铺 | actor / module / space / op / scope / reason 六项齐备 | ⏳ T1.1.1 |

## 验收时怎么判断「好用」

1. **一次真实对话跑完，`sqlite3 memory.db "SELECT kind,seq FROM mem_events ORDER BY seq"` 能看到完整轮次** —— 不是「模块跑通了」，是**我的对话在里面**。
2. **杀掉 daemon 再起来，上一轮对话的上下文还在**，且与崩溃前逐条相等。
3. **既有的跨模块隔离探针一条都没退化** —— 本轮任何改动都不得以牺牲 F1/F8 的隔离为代价。
4. **没出事故**：迁移后没有任何一条记忆读不到；`rekey` 在遇到它搬不动的表时**拒绝而不是静默孤儿化**。
5. **没有比机制更强的说法**：PR 与文档里不出现「schema 强制的模块隔离」「GDPR 就绪」「access control」这类本轮并不成立的措辞（F1 复审逐条列过的禁语）。

## 明确不在本轮验收范围

- 多用户 / 授权 / 部门 / workspace（ADR-030 的 M3，**等第二个真实用户**）
- 外部系统凭据管理
- 配额（F7）、symlink 安全（F6）、命名空间迁移（F3）
- 进程外 Provider（ME-3）、Cos72（ME-4）
