## 试点与发布门

1. 先内网标准部署、单用户授权样本，验证主对话只读 API；专用知识页不等待通用 Workspace。公开样本不是私有资料/组织隔离的验收替代。
2. Lite 打包、签名、下载体积/解压占用、Sidecar 版本/实例/能力就绪、退出与重启另立分发子任务；组织模式只连接服务器，不能由 Desktop 停共享服务。
3. profile 切换取消在途请求、重验身份/范围，不混搜和自动同步私有资料；数据库迁移为明确授权的导出/导入，不是配置切换。
4. 组织多人可用须单独过两用户两组织、撤权/来源删除、出口、缓存隔离、后台任务、备份恢复和审计门；未交付的组织/per-run 权限机制继续阻塞对应使用场景。
5. 非敏感公开样本可在已批准出口下验证；真实 LocalOnly 资料必须覆盖所有处理链路，不能因为当前 agent runs 的 Privacy 缺口而默认外传。
6. 重大费用、模型出口/Embedding 变更、大规模重索引、共享范围和原件生命周期改变按现有审批门执行。自动调优单列后续工作包，不作为首版可用的前提，不自动购买/扩权/删除原件。

## 用户可观察的完成定义

- 普通用户只在 Agent24 主对话沟通；重启后历史/个人记忆仍只有一个权威。
- 无需理解模型供应商、Embedding、向量库、分块或存储参数；只有资料处理位置、价格/配额及必要身份/用途信息以普通语言呈现。
- 激活、组织身份和资料出口/执行许可分别校验；不在客户端共享供应商根 Key，不在日志/配置仓库泄漏密码。
- 引用能打开对应原件/修订；取消和知识 Off 可观察；服务不可用给出恢复路径，不假成功。
- 组织事实与 SOP 不从未授权聊天自动发布；个人偏好不串入组织 KB，人工修订不被自动优化覆盖。
