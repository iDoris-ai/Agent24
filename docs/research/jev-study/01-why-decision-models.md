# 01 为什么需要决策模型：问题定义

> 本文只汇编仓库内已有材料。每个事实都标了出处（仓库相对路径或 PR 号）；作者的推断明确标「推断」。

## 1. 起点：M1 规则式「记住」识别的真实误判

Agent24 M1「记忆即产品」里，判断「用户是不是要我记住一件事」的是规则函数 `explicit_remember`（`rust/crates/agent24-agent/src/retain.rs`；评测用的版本是 `ab/m1-memory` @ `c503bf1`，含 M1-T13 修复，见 `eval/decide/README.md`「规则基线」节）。

真机验收里出现的原句（出处：`docs/research/DECISION-MODELS.md` §1；`eval/decide/retain_intent.jsonl` 的 `note` 字段）：

| 类型 | 原句 | 评测集 id | 说明 |
|---|---|---|---|
| 漏识别 | 「你记住，我对花生过敏。」 | ri-002 | 规则只认开头的「记住 / 请记住」；M1-T13 已修 |
| 误识别 | 「你记住我吗」 | ri-046 | 问句被当成记住指令（M1-T13 原始误识别句） |
| 误识别 | 「你记住他的名字了吗」 | ri-047 | 同上 |
| 陷阱 | 「你帮我记住这个好不好」 | ri-021 | A-不-A 问句；规则抽出的内容是「这个好不好」 |

`retain.rs` 被一修再修（PR #680，「句末疑问（吗/？/了吗）不再误识别为记住」，见提交 `bb81341`），但修完 M1-T13 之后，规则在 101 句中文评测集上的成绩仍是（出处：`eval/decide/README.md`「规则基线」节，PR #687 评审独立复算零偏差）：

- 33 条 `remember` 中**漏识别 15 条**（召回约 55%）；
- 68 条非 `remember` 中**误识别 8 条**（误写入率约 12%）。

规则漏掉和误判的句子本身就是好素材（出处：`eval/decide/retain_intent.jsonl` 中带 `rule_fn` / `rule_fp` 标签的条目）：

**漏识别（应当记住，规则没认出）**

| id | 原句 | 为什么规则认不出（`note`） |
|---|---|---|
| ri-011 | 你给我记好了，我老婆生日是3月8号 | 北方口语「给我记好了」 |
| ri-012 | 记下来：车牌号沪A12345 | 动词「记下来」不在规则表 |
| ri-013 | 这个你要记住：我的血型是O型 | 动词在句中 |
| ri-014 | 我对青霉素过敏，你记住哈 | 动词在句末 |
| ri-015 | 千万别忘了我对芒果过敏 | 否定词＋忘＝肯定的记住 |
| ri-018 | 帮我记牢，阿拉儿子礼拜三要打疫苗 | 沪语 |
| ri-019 | 记到起哈，我明天要早起赶飞机 | 川渝话「记到起」 |
| ri-024 | 你记住，我对花生过敏，好吗 | 句末「好吗」是礼貌请求，不是询问 |
| ri-030 | Please remember my wife's name is Anna | 规则只认 please remember that |

**误识别（不该写入，规则写了）**

| id | 原句 | 实际意图 |
|---|---|---|
| ri-062 | Remember when we went to Japan? Good times. | 询问记忆（规则把整句当内容） |
| ri-069 | 记住，我现在不住上海了，搬到杭州了 | 更正（规则当新增写入） |
| ri-080 | 你记住你是一个翻译助手 | 对助手角色的指令 |
| ri-086 | 记住一个人要多久 | 无问号的问句 |
| ri-087 | 帮我记住密码的方法有哪些 | 询问记忆技巧 |
| ri-088 | 记住我的话，你会后悔的 | 警告语气 |
| ri-100 | remember to drink water | 提醒，不是事实 |

结论（出处：`DECISION-MODELS.md` §1、§7.1）：中文口语、方言、句式位置、问句形式穷举不完；意图判断本质是**分类问题**。

## 2. 为什么不直接让生成式 LLM 来判断

1. **它会无视指令**：同一轮真机验收里，本地 Qwen3-8B 在 system 提示中已写明「记忆已暂停」，仍然回答「我记住了」（出处：`DECISION-MODELS.md` §7.1；PR #686 评审确认该事实与 #680/#683 的真实过程一致）。
2. **自报置信度过度自信**：ICLR 2024 的系统比较（arXiv 2306.13063）结论是 LLM 用口头表述给出置信度时普遍 overconfident（出处：`DECISION-MODELS-EVIDENCE-2026-10-06.md` §6）。
3. **logprob 也不是稳定的解**：arXiv 2609.10996 报告 post-2025 闭源模型上 verbalized confidence 反超 logprob 方案（同上 §6；该文给出的是经验结果，不是原因分析）。
4. **慢一个数量级**：Ollaya README 自家实测——encoder 类在 GPU 上 7–35ms、CPU 上 0.15–2.4s；decoder 类（小 LLM 当分类器）GPU 上 0.1–0.9s、CPU 上 1.3–25s（出处：`DECISION-MODELS-EVIDENCE-2026-10-06.md` §5「小 LLM + 约束解码」小节，标为已核实，但属厂商自测）。

因此 `DECISION-MODELS.md` §7.2 的判断是：「小 LLM + 约束解码 + logprob」**不作默认路线**，只在没有现成专用分类器时兜底；用 LLM 模拟出来的结果必须标 `backend=llm_simulation`，不得冒充校准概率（这一条后来写进了代码，见 `03-architecture.md`）。

决策模型（Jev / Laya / GLiClass / NLI 类）的特征：不生成文字，只对「一段输入 + 结构化问题」返回「标签 + 概率」（出处：`DECISION-MODELS.md` §1）。概率可以设阈值、可以评测、可以回归——这是它相对 prompt 判断的核心价值。

## 3. 19 个判断点的三分类

出处：`docs/research/DECISION-POINTS-INVENTORY-2026-10-06.md`（逐点盘点，含位置、现在怎么判、判错后果）；分类结论见 `DECISION-MODELS.md` §7.1。

| 类别 | 判断点（盘点编号） | 处理 |
|---|---|---|
| **A. 安全 / 一致性不变量** | #2 WriteGate 信任策略、#5/#15 来源（trust）标记、#6 召回的 owner/active 过滤、#8 会话导入、#10 Authorizer、#16 capability 令牌、#11 会话视图 | **不引入模型**，永远是确定性代码 |
| **B. 语言理解类判断** | #1/#9 记住意图与疑问句拒绝、#19 召回门控、#4 Guardian 工具风险、#13 入口路由 / TaskProfile、#17 入站消息分类、#18 PII 识别、#14 语音句子边界与意图 | 规则兜底 + 决策模型 + 弃权带 |
| **C. 暂不需要** | #7 摘要触发（计数即可）、#12 审批类型 | 维持现状 |

注：盘点表共 19 行，#3 ModelRouter 提供商选择在 §7.1 的三分类表中未单独列出（它在 B 类 #13 TaskProfile 生成之后，按画像矩阵确定性排序）。这一点是本目录作者对照两份文档发现的，**未见 jason 的明确归类**。

另有引入决策模型后自然出现的新场景（`DECISION-MODELS.md` §7.1）：纠错识别（「不对，我说的是…」）、偏好指令识别（「以后用中文回复」）、是否反问澄清、Agent 循环卡住检测、上下文是否需要压缩。

## 4. 为什么 A 类必须留给确定性代码

依据 `DECISION-POINTS-INVENTORY-2026-10-06.md`「判错后果」列与 `DECISION-MODELS.md` §7.3、§7.5：

1. **它们是权限与一致性的边界，判错没有「概率上可以接受」的余地**。例：Authorizer（#10）判错就是泄露其他模块的数据；召回的 owner 过滤（#6）判错就是召回他人数据；来源标记（#5/#15）标错会让 WriteGate 的决策「全盘错」。
2. **概率模型可以被对抗**：`DECISION-MODELS.md` §7.5 把「概率模型被提示注入或对抗改写」列为风险，对策是它「只能建议更严，不能放宽 A 类不变量」。EVIDENCE §6 也收录了对抗性改写让分类器准确率骤降的研究（WebSearch 聚合，标已核实）。
3. **单向收紧原则**（`docs/agent/PLAN-DECIDE.md` §0、`docs/decision.md` ADR-033 第 4 条）：决策服务的输出只能触发「建议」或「更严格」的动作（执行 / 反问 / 交人），类型系统里没有能越过审批门、WriteGate、Authorizer 的出口。
4. **人工确认本身也可能被操纵**：EVIDENCE §8 记录了 2026 年「确认文案被攻击者控制，人工确认形同虚设」的反向风险（标「弱已核实」），所以确认 UI 的文案也要走可信渲染（`DECISION-MODELS.md` §7.5）。

## 5. 一句话

规则是精度高但覆盖窄的地板；生成式 LLM 覆盖广但不可校准、会无视指令；专用决策模型输出可阈值化的概率，适合 B 类「理解语言」的判断——但前提是先在自己的中文评测集上证明它（中文评测的空白见 `02-ecosystem-survey.md`、`04-evaluation-design.md`）。
