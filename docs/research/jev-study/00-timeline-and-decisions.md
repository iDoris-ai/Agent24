## 起因（2026-10-06）

- M1「记忆即产品」真机验收时，规则式的「记住」意图识别（`retain.rs` 的 `explicit_remember`）出了两类错：
  - **漏识别**：「你记住，我对花生过敏。」没有被识别（规则只认开头的「记住 / 请记住」）。
  - **误识别**：「你记住我吗」「你记住他的名字了吗」被当成了记住指令。之后 PR-Daemon 又发现「你帮我记住这个好不好 / 行不行 / 对不对」这类 A-不-A 问句也会误判。
- 另外观察到：本地 Qwen3-8B 在 system 提示里已经写明「记忆已暂停」，仍然回答「我记住了」。这说明用生成式 LLM 当判断器，结果不可靠。
- jason 的判断：靠 prompt 和规则太笨，要引入「决策模型」（Jev / Laya / Ollaya 一类）。拍板把它定为 **M1 之后第一项（DM-SPIKE）**，并持续跟进调研。

## 调研与方案（2026-10-06 → 10-07）

- 盘点了 Agent24 内全部 19 个判断点，分三类：
  - **A 类（7 个）**：安全和一致性不变量，必须保持确定性代码；
  - **B 类**：语言理解类判断，适合决策模型；
  - **C 类**：暂不需要动。
- 外部调研结论：
  - **Jev 闭源**，只借用它的接口形态（choice / noul / score，三类问题都附带概率）。
  - **「小 LLM + 约束解码 + logprob」不作默认方案**：比专用 encoder 慢一个数量级。
  - **中文没有现成可信的基准**。
- 方案：新建决策服务 `agent24-decide`。
  - 判断流程：规则先判 → 规则没命中时交给快速模型 → 复杂情况交给深度模型；
  - 阈值分三段：执行 / 弃权或反问 / 交人审批；
  - 不允许静默降级；
  - 决策全量记日志。
- PR #684（调研台账）。**jason 2026-10-07 同意方案和 D0–D3 分段**，并追加两条要求：
  1. **按用户电脑自动适配**，不同硬件用不同的决策模型；
  2. **从第一天起积累数据**，为训练用户自己的决策模型（个人版 Jev）打基础。

## 过程中的教训（可写进文章）

1. **规则穷举不完**：中文口语的问句陷阱一修再修。
2. **生成式 LLM 当判断器不可靠**：它会无视 system 提示，而且自报的置信度偏高。
3. **小 PR 评审的价值**：3 个真实缺陷都是在小 PR 评审里抓到的，涉及校准标记、阈值方向、版本 pin。
4. **训练集与评测集泄漏**：一开始只断言「逐字不重叠」不够，必须做近似重复检测（字符 n-gram，阈值 0.7）。
5. **硬件假设要实测**：「24GB 的 Mac mini」实际是 16GB；在 16GB 上，SetFit 训练会把内存压进重度 swap。
6. **训练和推理要分开**：用户机器只做推理，训练在开发机上做一次，再分发产物。
7. **生态里自报的成绩多、许可证不明的多、中文证据少**（见 02）。
