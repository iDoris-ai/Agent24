**1. 结论**

1. **保留 Agent24 本体，增量补齐持续工作的运行机制。** 不建议迁移到 Harness，也不建议另建一个总控产品。调度、记忆、审批与执行权威继续归 daemon，符合 ADR-039 §2–3、ADR-037 决策 1。
2. **最重要的新增边界是“用户要完成的工作”与“一次 run”分离。** 工作应跨会话、执行尝试和重启保持身份；run 成功、产物生成、对外交付、用户验收分别记录。当前恢复主要覆盖等待审批的 run，不能承担完整持续工作语义。〔`agent24-agent/src/resume.rs::plan_resume`〕
3. **先保护记忆与恢复，再扩展自主性。** CORE-5 协调器仍关闭，记忆打开失败仍可无记忆继续启动；优先完成 5f–5i 对应链路，组件契约与技能契约可并行推进。〔`migration_coordinator.rs:20`、`server.rs::open_memory_base`；CORE-5 §4〕
4. **学习事件准入、持久状态、交付对账和上下文预算；不复制云端权威、全权限执行及在线自改安全规则。** 原型明确是研究代码，部署预设使用 `danger-full-access`，与 Agent24 产品边界不相容。〔[原型 README](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/6337fc823ce20251c8de8085948165c81aaa701e/README.md)、[部署文档](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/6337fc823ce20251c8de8085948165c81aaa701e/docs/006-deployment.md)〕
5. **自进化从可验证的技能升级开始。** 技能必须版本化、评测、审批、回滚；长期记忆和模型训练分别治理，训练归 iDoris，不把三者合成一个自动学习开关。〔ADR-039 §3；可进化性评估“建议”§4–6〕

**2. Super Agent 框架要点**

需要区分三层材料：**设计探索、公开原型、博客新增工程建议**。原型 README 明确指出三者并不完全一致。

| 方面 | 可确认的要点及边界 |
|---|---|
| 分层 | 面向人的协调与具体执行分开；执行上下文彼此隔离。计算、状态、执行环境可分离，但不必部署在云端。前者见原型文档；云端方案来自 `SOURCES.md` §3，原文未亲自核对。 |
| 组件 | 原型以 Runtime 组合依赖，Engine 承担领域写入，外接 Source、Assessor、Executor、Store、Outbox。Harness 是宿主，Cordis 是插件底座，三者不是同一个框架层。〔[架构文档](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/6337fc823ce20251c8de8085948165c81aaa701e/docs/007-architecture.md)、[Harness](https://github.com/deepseek-ai/deepseek-harness)〕 |
| 运行循环 | 事件接入 → 程序准入 → 必要时模型研判 → 创建或继续工作 → 独立执行 → 汇报／交付 → 等待新事件或验收。已订阅的后续上下文可以直达执行方。〔[领域模型](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/6337fc823ce20251c8de8085948165c81aaa701e/docs/001-domain.md)〕 |
| 事件与状态 | 事件、讨论归属、工作、授权依据、执行尝试分别保存；状态改变与待执行动作先提交，再访问外部系统。不是“保存聊天记录就能恢复”。〔领域模型；架构文档〕 |
| 记忆 | Inline／Spill、稳定引用、分页和按需展开用于控制上下文；它们没有解决全部长期记忆、删除、迁移与跨月一致性问题。〔`SOURCES.md` §2、§3〕 |
| 工具／技能 | 后台操作应有作业身份、取消和完成反馈；工具及插件生命周期属于宿主。不能由此推导出原型已经实现技能版本、评测与审批闭环。〔[执行文档](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/6337fc823ce20251c8de8085948165c81aaa701e/docs/003-execution.md)、[Cordis 入门](https://deepseek-harness.github.io/deepseek-harness/reference/cordis-primer)〕 |
| 多 agent | 并行执行独立工作，子任务保持隔离；订阅提供必要关联，不要求默认建立任意互聊网络。具体并发槽、后台任务和交接有独立生命周期。〔执行文档〕 |
| 自进化 | 设计讨论中的监督者可以建议甚至调整运行行为；**尚不能据此认定已具备安全、可验证的自进化系统**。〔`SOURCES.md` §2、§3；原型 README〕 |
| 评测 | 应分别评测调度正确性、模型判断质量和真实交付。合成消息、等待工具和离线替身测试不能证明真实修复能力提升。实验本身未复跑。〔`SOURCES.md` §2、§3〕 |
| 安全 | 订阅只增加上下文，不扩大授权；外部消息不是权限指令。原型的账号包装不等于 OS 隔离。〔[授权文档](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/6337fc823ce20251c8de8085948165c81aaa701e/docs/002-authorization.md)、部署文档〕 |
| 工程实践 | 持久化待执行动作、回执、退避、对账和故障注入值得借鉴。GitHub 适配器通过消息标记查重，但没有跨 SQLite 与 GitHub 的全局 exactly-once 保证。〔[Outbox 源码](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/6337fc823ce20251c8de8085948165c81aaa701e/src/app/outbox.ts)、[GitHub 发送源码](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/6337fc823ce20251c8de8085948165c81aaa701e/src/sources/github-channel.ts)〕 |

**4. 该学的、不该学的**

| 选择 | 理由与 Agent24 落点 |
|---|---|
| **学：程序先准入，模型后研判** | 降低无效模型调用；更关键的是把身份与权限判断留在确定性代码。复用 K1 与 capability token 权威，模型只判断是否值得做、如何做。〔K1-01 §2.1；原型授权文档〕 |
| **学：工作身份独立于执行会话** | daemon、模型或执行进程重启后，用户目标与验收条件仍应存在；在现有 run 上层增加内部持久记录，复用 run 执行。〔当前 `plan_resume` 的范围限制〕 |
| **学：状态与待执行动作原子提交、外部结果对账** | 解决“决定已保存但未执行”“已发送但回执丢失”；必须按动作分类恢复，不能统一重试。〔原型 Outbox；K1-01 §2.5–2.6〕 |
| **学：上下文按需展开与生命周期释放** | 保留来源、稳定引用和预算；能力卸载时同步清理工具注册、监听与排队引用。〔记忆来源 ADR；Cordis 入门〕 |
| **学：用有效交付与人类介入成本衡量进步** | 并发数、模型自报进展、日志更新都不是价值证明。〔原型执行文档；本次建议〕 |
| **不学：云端是权威、本地只是执行手脚** | 与本地优先、个人数字分身及 daemon 本体冲突。可分离计算，但状态、授权及用户控制权保留本地。〔ADR-039 §2.1；ADR-037〕 |
| **不学：所有东西都插件化** | 审批、记忆、调度等已被 ADR-039 划入本体；插件依赖注入可以借鉴，不能让安装包替换安全权威。〔ADR-039 §2–3〕 |
| **不学：执行者／监督者默认全权限** | 原型部署做法不满足 Agent24 的 fail-closed 审批边界。监督者也只能提出或执行获准动作。〔部署文档；K1-03〕 |
| **不学：自动扩权的投机执行和自修改** | 草稿、读取也可能涉及隐私与成本；只能在预先授权范围内试做。技能评测通过不授权外发、部署或修改审批规则。〔K1-03 草稿补遗；ADR-039 §3〕 |

**5. 与 ADR-039／ADR-038 的关系**

**ADR-039 应保持总纲地位。**

- 协调、事件准入、工作状态、恢复和监督均属**本体内部实现**；不要新增对外的 Agent、工作流、插件等顶层分类。
- 来源接入、通信投递、具体处理工具可由**能力**提供；能力只提交事件或请求，不能指定运行哪个技能。
- 用户目标的可复用步骤属**技能**；临时工作不必先包装成技能，工作记录和 run 都是内部对象。
- 建议补一条解释：**模型生成的计划、事件订阅与技能版本都不是授权凭证**。执行权限仍来自现有审批与 capability token。〔ADR-039 §3、§5〕

**ADR-038 应补边界，不扩大成总运行时规范。**

1. **D8／D9 补“可替换”的充分条件。** 同一能力 id、契约名和 major 不足以证明业务语义相同。技能依赖能力 id，但工具名包含组件 id；须定义运行时绑定记录和兼容用例，覆盖参数、输出、副作用、隐私与取消。一次运行固定选中的提供者及契约，不能执行中静默换品牌。
2. **D5／C8 补状态权威。** 桌面上报的安装／运行状态是观察值，不能授予工具许可；需要身份、代际、过期与失联语义。`ready` 不等于已授权，也不等于某次工作完成。
3. **D6 保留默认不重试。** 后续持久动作 ADR 只为明确支持幂等或对账的操作建立窄例外，不能通过公共重试队列架空 K1-01。
4. **D9 的技能占位由 ADR-040 接管。** 组件附带技能也必须独立记录内容摘要、版本、评测和激活审批；升级能力不能顺带静默替换技能。

依据：[ADR-038 D5–D9、C8](docs/adr/ADR-038-component-contract-v1.md)、[ADR-039](docs/adr/ADR-039-concept-model.md)。

另有一处应明确裁决：上午评估建议“技能评测门槛以后再加”，但随后已接受的 **ADR-039 要求改动通过评测**；后续计划应服从 ADR-039。

**6. 分阶段演进路线**

以下按依赖排期，不承诺未经估算的日历工期。

| 阶段 | 目标 | 前置 | 交付物 | 验收标准 |
|---|---|---|---|---|
| **P0：保护现有身份与记忆** | 升级失败不静默失忆，不自动重试迁移 | CORE-5 5a–5e 及 CORE-4 契约；确认已落地依赖 | **5f** 停靠／协议、**5g** 外壳识别后共同启用；**5h** 安装器回退；**5i** 在 CORE-2 证明链就绪后开放授权 retry | 双库及 FTS 失败注入、持久边界重启；停靠无业务执行；桌面／CLI 不另起实例；旧授权不能 retry。依据 CORE-5 T1–T15。 |
| **P1：统一能力，交付最小技能** | 能力可发现、可替换；技能可安装和回滚 | ADR-038／040 接受；P0 不阻塞只读设计工作 | **C1→C3**；C4 AgentEar、C5 Knowledge、C6 Documents、C7 领域包／MCP 清单与登记表、C8 桌面上报。**C2 等 relay 上线，C1b 等签名版发布**。ADR-040 加载、依赖解析、版本及评测 | ADR-038 §3 反例；第二提供者替换用例；零依赖技能和跨能力技能各一例；缺依赖、多提供者未选择、权限扩大均明确拒绝。 |
| **P2：先实现单项工作的持续恢复** | 同一用户目标跨事件、会话和重启保持连续 | P0；现有 K1 工具门；ADR-041／042 | 单一来源的持久接入、准入记录、工作与 run 关联、执行尝试、待交付记录；先影子回放，再开放限定动作 | 重复事件不重复接单；状态提交后崩溃可恢复；旧执行结果不能覆盖新尝试；未知外部结果先对账；run 成功不自动验收。 |
| **P3：补齐记忆版本与有界上下文** | 持续工作能长期运行，并尊重更正／删除 | 现有记忆来源与生命周期设计；P0；ADR-043 | 版本化导出格式、恢复验证、稳定引用、分页预算；召回入口注入 `Retriever`；向量重算先 CLI，按质量证据决定接入 | 第二检索实现通过同一契约；旧包不能复活删除内容；恢复后来源／owner 不漂移；断点、满盘、索引损坏可验证恢复。离线恢复受既定信任锚约束。 |
| **P4：受控并行与独立监督** | 多项工作同时推进且用户可随时介入 | P2 稳定；执行资源隔离、权限接线通过；ADR-044 | 有界并发、每项工作预算、取消／暂停、资源写入冲突控制、确定性进展检查；之后才加模型偏航评审 | 一项工作阻塞不拖死其余；同资源写入无静默覆盖；暂停后不自动恢复；监督者无法扩权；并发增益用真实完成率和人类介入时间证明。 |
| **P5：受控技能进化** | 有证据地改进技能 | ADR-040、P4 评测体系、稳定运行基线 | 失败样本→候选版本→隔离评测→人工批准→激活→可回滚；训练另属 iDoris，Agent24 仅提供明确同意的数据导出 | 候选不能改评分器或隐藏失败；旧 run 固定旧版本；回滚不恢复已撤销权限／已删除数据；默认无数据上送。 |

路线中的两条并行约束：

- C1–C8 不必全部结束才试验持续工作；只使用**已经验收的能力**，不为赶演示绕过缺口。
- P2 可以先采用现有有界召回；P3 的导入／防复活闭环完成前，不承诺跨版本、跨机的完整长期恢复。

发布仍按用户给定工作流：task PR 进入对应 `ab/*`，敏感改动等远端 APPROVE；release 由人开，并用全新数据目录、真实 daemon、CLI 用户操作流程验收。表中的标准均是**未来验收要求，本次未运行**。

**7. ADR 草案：ADR-040—ADR-044**

以下均为**待拍板草案**，不是新增顶层产品概念。

**ADR-040：技能契约、依赖绑定与受控升级**

- **决策**：技能清单包含 id、版本、来源、内容摘要、说明／步骤、能力依赖、评测用例和兼容要求；社区 `SKILL.md` 导入后先成为未激活候选。技能不持有权限。运行固定技能版本及能力提供者绑定；激活必须评测、审批、留审计，可切回旧版本。
- **备选及否决**：只加载 Markdown——不能可靠追踪版本与依赖；技能携带权限——违反 ADR-039；每次运行自动取最新版——不可复现且改变已批准行为。
- **后果**：安装、激活、执行分开；零依赖技能也受版本与评测约束。回滚只改变后续执行版本，不撤销已经发生的外部动作。
- **开放问题**：社区格式支持子集；首版评测最低标准；依赖版本约束和提供者绑定如何与 ADR-038 D9 对齐。
- **依据**：ADR-039 §2.3、§3、§6；ADR-038 D8–D9。

**ADR-041：本体的事件准入与持续工作状态**

- **决策**：本体持久保存来源事件身份、讨论关联、准入决定、用户工作、执行尝试及授权引用。工作关联一至多个 run；同一事件重复提交不重复接单。订阅只投递上下文，扩范围必须重新经过授权判断；人工停止不能被普通后续事件自动解除。
- **备选及否决**：以 session／run 作为唯一身份——无法表达换执行、等待交付和跨会话继续；照搬 Ticket／Mandate 为产品概念——违反 ADR-039，且易制造第二套权限权威。
- **后果**：新增少量持久领域状态，但继续复用 RunManager；来源身份不能仅凭相同用户名跨平台合并。工作状态与授权有效性独立。
- **开放问题**：首个事件来源；完成后的工作何时允许重开；事件保留期限、来源删除和隐私策略。
- **依据**：原型领域／授权文档；`resume.rs::plan_resume`；ADR-039 §3。

**ADR-042：外部动作、交付回执与恢复对账**

- **决策**：工作状态与动作意图在同一事务保存，事务提交后派发。区分业务动作身份与每次调用身份；绑定目标、载荷摘要、执行代际、授权引用。默认不自动重试工具写操作；只有明确声明且验证过幂等／查询契约的动作才允许恢复重投，否则进入 `result_unknown` 并等待对账或人工决定。
- **备选及否决**：所有失败指数退避重试——可能重复副作用；永不恢复任何动作——容易丢失交付；宣称全局 exactly-once——跨外部服务没有共同事务。
- **后果**：通道需提供去重或对账适配；重试前重新校验当前权限。区分执行完成、交付确认、验收通过；取消不代表已发生副作用被回滚。
- **开放问题**：哪些首版操作具备足够对账条件；幂等键保留多久；同键不同载荷、进程崩溃和外部查询延迟怎样处理。
- **依据**：K1-01 §2.5–2.6、ADR-038 D6；原型 Outbox／GitHub 发送源码。此 ADR 必须明确其对既有“不重试”规则的窄例外范围。

**ADR-043：版本化记忆与持续工作的上下文引用**

- **决策**：记忆仍归本体；版本分别覆盖交换格式、数据水位及派生索引配置。上下文使用稳定对象／修订引用，分页和预算由本体强制；召回、更正、撤回与恢复执行同一资格检查。检索替换先收口召回入口，不整体重写存储。
- **备选及否决**：聊天摘要作为全部长期记忆——来源与更正不可追踪；复制数据库文件即视为迁移——缺身份、格式和删除世代验证；将记忆变成可卸载能力——违反 ADR-039。
- **后果**：技能回滚、工作恢复、索引重建都不得复活已删除内容。延续生命周期 ADR 已决的认证加密、恢复锚与全个人域清除边界，不另创相冲突方案。
- **开放问题**：交换格式精确版本；恢复锚的实现和可用性；审计引用与正文删除的协调；向量接入的质量门槛。
- **依据**：`SessionMemory`；[记忆生命周期 ADR §6、§9](docs/adr/ADR-MEMORY-P1-LIFECYCLE-AND-PURGE.md)；记忆来源 ADR；CORE-5。

**ADR-044：有界并行、独立监督与交付评测**

- **决策**：并发、预算和资源写入归本体管理。监督先用队列年龄、失败次数、有效产物和验收进度等确定性证据；模型只补充偏航建议。监督者无权限修改授权规则、突破暂停或自动激活技能候选。评测覆盖准入、执行、安全、恢复、交付及人类介入成本。
- **备选及否决**：仅监控进程健康——不能发现空转；给监督者完整权限自修——形成第二个高权限失控点；只测模型基准——不能证明产品交付可靠。
- **后果**：需要可比较的基线、固定用例及故障注入；候选技能不得修改验收器。训练与监督分离，训练仍归 iDoris，个人数据不默认上传。
- **开放问题**：首版并发上限与本机资源预算；何种停滞可自动暂停；模型评审误报如何测量；成本和质量退化到什么程度阻止激活。
- **依据**：`subagent.rs`、`guardian.rs`、现有专项评测；ADR-039 §3；本次提出的持续工作验收要求。

**8. 最需要裁判关注的三个点**

1. **不要把“有持久记录”当作“可恢复且已交付”。** Agent24 已有调度投递，原型已有 Outbox，但工作恢复、工具副作用、外部确认、用户验收仍是不同问题。重点审 ADR-041／042 是否准确处理 `result_unknown`、旧执行回报及重启后重复动作。〔`deliveries.rs`、`resume.rs`；K1-01 §2.5–2.6〕

2. **不要让持续性突破权限和删除边界。** 新事件、订阅、旧审批、记忆备份、技能回滚都不能恢复已撤销权限或已删除数据。哈希链只能证明其定义范围内的链完整性，不能替代外部新鲜度锚、授权或 OS 隔离。〔K1-02／03／04；记忆生命周期 ADR §9〕

3. **不要把契约命名一致、组件已实现当成产品可替换。** 能力 id 相同不证明工具语义一致；C8 状态上报不证明 daemon 已拥有执行权威；已有 capability token 和 workspace 代码不证明 ACP 产品路径已使用。每个阶段都应通过真实入口证明接线，并用第二实现证明替换。〔ADR-038 D8–D9；`acp.rs` 的 `workspace_id: None`；`ARCHITECTURE-LAYERS.md` §6〕
