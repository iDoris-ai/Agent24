## 1. 修订结论：先证明收益，再扩治理

初稿“先花 16–23 人日做完整治理核心，再智能化”过于基础设施导向，尚未证明它比更小路线适合当前产品。**推荐改为 A → B0，证据成立后才 B1/B2。不是宣称全局最优。**

| 路线 | 当前收益 / 改动 / 风险 | 建议 |
|---|---|---|
| A：保留 M1，真实路径基线 | 不改架构；厘清已有能力与问题；暂不证明归纳收益 | 必做起点，也可以是最终选择 |
| B：一个固定问题的偏好页 | 借鉴“预计算答案”；单 owner、只读、直接依赖已确认断言；可关闭丢弃 | **首选验证路线**，先离线/预览再受控缓存 |
| C：完整治理核心 | 更正与可控性有独立价值，但跨度更大，不直接证明 Hindsight 的归纳收益 | 明确更正需求可独立推进；通用部分等 B 证据 |
| D：接入 Hindsight 服务 | 新运行栈、权威/权限映射和迁移负担；已有 SQLite/账本/向量接缝被重复 | 当前不推荐；不能以榜单替代本地收益证明 |

最小固定问题例如：“用户明确记住了哪些交流偏好？有哪些临时限制或冲突？”只用合成样本或另外授权的个人数据，不从全部聊天构建人物画像。

**同一来源、问题、模型/回答配置、上下文预算比较三组：**原始记忆列表 → 确定性摘录页 → 模型归纳页。若模型页没有在正确性、证据覆盖、token/摊销成本或用户体验上取得净收益，保留确定性页或 A；不能为了“学到了文章”强行上模型。

M1 原文/明确记住/查看搜索/撤回暂停保持不动；不迁移到 Hindsight，不造第二套个人权威，不先建通用依赖图、多层记忆数据库或自治 Agent。

## 3. 首选试点：一个有根证据的预计算页

```text
当前 owner 的合格、已确认断言
  → 有界完整来源快照 / 用途 / policy epoch / 世代
  → 确定性摘录，或事务外模型生成
  → 输出验证 / 根证据去重 / 每条结论引用
  → 预览（B0，不自动进入生产 recall）
  → [仅在过门且另获批准后] 可丢弃缓存（B1）
  → [再次明确用途同意] 相关问题的受控读取（B2）
```

### 3.1 范围与可见收益

- 单 owner、一个问题/页面类型；优先少量明确偏好，不抽取全部事件，不引入图检索或跨用户共享。
- B0 先用合成数据验证长列表能否更省预算地回答固定问题，并正确呈现期限、冲突与未知。
- B1/B2 不是自动继承 B0 的授权；缓存、后台刷新与跨会话使用分别明确开启。
- 页面按相关用途读取，不作为每轮“用户人格”常驻注入；陈旧时退回当前有效账本，或不注入。
- 每个结论带直接根断言/事件引用与短引文。页不引用页，不用助手复述生成新证据；首版不需要通用 DAG，整页失效即可。

### 3.2 来源世代与集合 freshness

只查 `assertion_id` 是否 active 不够：同 ID 可撤回→重记；新增相反事实也可能不改变旧页已引用的条目。

B0 对有界完整合格来源集合生成签名：包括 owner、来源内容/evidence/状态与资格、用途、policy epoch、生产器/prompt/配置版本、查询时间语义。不能只 hash 被模型选中的条目。

持久 B1 需要 host 控制的单调 owner revision 或等效不回退世代，**每次相关写入/撤回/更正/重新授权都递增**；最终内容相同也不能重用旧世代（ABA）。各写入口必须原子更新，不能依赖同秒时间戳或仅靠最终内容 hash。来源集合新增/删除/冲突都会令页失效；首版保守整页重建，不先设计实体级增量图。

valid-time 边界变化没有写事件也可能使页过期；缓存须记录适用时点/用途，并在读时校验时间资格/到期边界。后台及时刷新不是安全前提。

### 3.3 最小异步构建与发布协议（仅 B1）

1. 捕获有界来源、世代、用途/policy epoch、生产器版本，形成幂等缓存 key；不由模型指定 owner/trust。
2. 建立有期限租约/任务状态，限制队列、调用预算、重试次数和结果大小；取消/重启可恢复。
3. 事务外生成，不把网络或模型调用放进 SQLite 写事务，不改 CountSynth/InsightSynth 既有契约。
4. 验证闭合 schema、长度、引用白名单、引用 owner/资格、引文与时间；未知字段/伪造来源拒绝。
5. 合法引用不证明蕴含；逐结论检查来源是否支持，试点用人工/独立评估，不能由生成模型独自证明自己正确。
6. 短事务重查当前暂停、用途同意、epoch、来源集合/世代；CAS 失败丢弃结果或置 stale，不能发布 ready。
7. 原子发布 accepted result/状态/审计；ready 后重试复用已接受结果，不重新调用假装确定性。
8. 清理过期租约/失败任务/陈旧缓存；提交前崩溃可能导致有界重复调用，**不承诺模型 exactly-once**。

生成中暂停/撤权后，缓存、模型候选 Held 和断言 Commit 都不能凭旧授权迟到持久提交。候选为 Held 也不是绕过暂停的理由；各写路径需要同事务政策检查。

### 3.4 不可变快照与当前 request view

保留历史 input snapshot 作为事实记录；**每次真的向模型发送请求前**，从它构造当前允许的 request view：按身份、暂停、用途同意、来源世代/状态裁剪 typed memory block。审批唤醒、同进程恢复、冷启动恢复与普通发送同样检查。

Derived 明确标“模型归纳/推断”，不沿用“用户明确要求记住”的文案；不改变 system、工具授权或行为策略。资格无法证明时对记忆块 fail closed；旧快照须有明确兼容策略，不能靠任意字符串替换删原文，无法安全区分时不继续发送不明记忆块。

审计记录 actual request view 的来源版本/IDs、裁剪原因和 digest，而非只记录最初 recall 列表；不为审计重复记录敏感原文。已发送的外部请求不能事后撤销，这与暂停后的后续发送阻断是不同边界。

撤回保证的是当前记忆/派生通道不再提供该事实，不是抹去仍保留的聊天原文或已发送内容。物理 purge 涉及 M1 no-loss 决定，须独立 ADR/授权，本提案不承诺。

## 4. 用途同意与审批：避免两个极端

| 用途 | 首版默认 / 同意 | 是否逐条人工确认 |
|---|---|---|
| 当前授权来源的临时只读预览/Reflect | 用户明确请求；推断带证据与标签；不持久化、不授予工具 | 不需要把每句临时推理都审批 |
| 派生页持久缓存 | 单独 opt-in、可关闭、可重建、仅私有投影 | 可按明确页面用途同意，不把每句摘要变成权威 |
| 后台刷新 | 另行同意，暂停/epoch/预算/取消可执行 | 不默认每轮运行；不得借旧授权补扫历史 |
| 跨会话注入派生页 | 另行同意，按相关问题读取并做发送前资格校验 | 不是缓存授权的自动附赠 |
| 新的 durable Model belief/偏好断言 | 模型只产生 Held；通过现有 WriteGate 与确认流程 | 需要确认；不得因“摘要”静默绕过写门 |
| 行为指令、工具权限、共享 SOP | 本提案不开放 | 各自明确授权/人审，记忆不能授予权限 |

同源复制、十次助手复述、被重复引用不会增加独立证据；模型结论不能因用户确认而改写为 UserSaid。确认本身可以是新事件，但不重写旧来源。

证据展开使用 host 身份和受限读取，foreign ID 不泄漏存在性；知识页、缓存和审计需有容量/保留/用途边界，不能成为第二套无限增长历史。

## 5. 独立后续工作：更正与检索不绑在试点上

### 5.1 显式更正（P1 候选）

有用户需要即可独立排期；不依赖 B 的通用图引擎，也不重开 M1。

建议私有更正服务/个人 API 契约：old ID + replacement + expected version + 幂等键；owner 由 host 注入。同事务验证 owner/版本/暂停与幂等，新值、旧值退出当前视图、来源世代、审计与失效原子提交。相同幂等键不同内容返回冲突；他人 ID 不泄漏；失败整体回滚。

先做用户选定某条记忆明确更正，不做模型自动合并同义句或裁定冲突。F11 的 asserted_by/冲突并存曾移出 M1/P0，批准后才落后续计划。

双时态字段已存在，但当前 reassert/过滤接缝不等于完整历史查询。需独立冻结 recorded-time/valid-time、未来 valid_from/已过 valid_to、未知时间和更正语义；所有读取在 LIMIT/排序/融合前统一资格，不以普通撤回冒充真实时间更正，不捏造未知日期。

重复“撤回→同句重记→再撤回”的审计 ID 冲突是源码审查发现的待反面对照风险；本轮未运行复现、更未修复。若证实真 bug，应单独最小修复，不把全部治理打包为其前置。

### 5.2 混合召回与候选抽取（P2 候选）

仅在 A 显示检索瓶颈后评估现有 FTS + 已获授权的本地 Embedder + RRF 去重/预算，不把 HashEmbedder 当语义收益，不先加图/reranker。部分索引、超时、模型版本变化和资源不足要实测 FTS 降级；B0 不依赖它。

自动候选抽取后置：默认关、可取消、结构验证、Held 审阅、用户负担评估。当前暂停期对话无摄入标记，历史未知资格默认不补扫；历史回填需单独明确授权。

### 5.3 巩固/经验（P5 候选）

B 只验证单类偏好页，不是全量巩固正式交付。扩到项目页/经验须另审：条件—操作—观测结果—限制—根证据。测试结果、用户验收等是证据；Agent 自评不能证明成功。观察/经验不自动升级成工具指令或共享 SOP。

## 7. 依赖与小 PR

```text
A → 用途/来源/评测契约 → B0 → [收益 go + 新授权] → B1 → B2
                  └→ 显式更正候选（可独立，不等图引擎）
A 证明召回瓶颈 + 已授权模型 → 可选混合召回
摄入资格/历史 opt-in/原子政策与审阅 UX → 后置候选抽取

```

核心/存储与 UI mock/工装可在契约批准后并行；安全检查不能因 UI 并行而省掉。研究包标记不是正式任务 ID，不创建全局里程碑或接管 K1/KB/暂停 Workspace。

不承诺固定“10–16 个 PR”：按实际补丁生产行数/文件/目录门和 API 依赖重估。按本机最新全局约定及原版检查器，默认 ≤300 **生产代码行**，测试/文档/锁与生成物按检查器排除口径，不沿用旧文本把测试计入生产预算。

未来执行限笔记本，共享 CARGO_TARGET_DIR；Rust fmt/clippy/workspace、涉及的 pnpm/API 漂移和原版 pre-pr-check，反面对照先红后绿。实现者≠验收者。所有任务 PR 仍需外部 PR-Daemon 精确 head APPROVE、required CI 全绿且 mergeable；三条件满足按用户常设授权立即合并，release 到 main 仍人开人审。研究审查不替代此门。

## 8. 验收与 stop/go

B0 可先 40–60 个中文为主、兼顾英文/泰文的合成案例；只是试点规模，不替代既有 P2 抽取/检索更大评测目标（至少 100 条目标应复核权威计划）。同来源、同预算、同回答配置比较三组；关键副作用用确定性断言，不让同一生成模型自评通过。

| 类别 | 必须覆盖 |
|---|---|
| 世代/来源 | 同 ID 撤回→重记→再撤回、同秒切换、旧来源未变但新增相反事实、重新授权、复制/助手回声不增证据 |
| 模型证据 | 合法 ID 不支持 claim、伪造引文/owner/trust、跨 owner evidence、未知 schema、临时/否定/引述/假设、冲突不可强行统一 |
| 时间/更正 | future valid_from、past valid_to、未知时间、同幂等键不同内容、版本冲突、事务回滚、资格在 LIMIT 前 |
| 暂停/恢复 | 生成中暂停/撤权、Held 迟到、审批唤醒、同进程与冷启动恢复、旧 snapshot、取消/崩溃/租约过期/有界重试 |
| 请求/权限 | Derived 不变 UserSaid、恶意“忽略权限”数据不获工具权、foreign ID 不泄漏、审计与 actual view 一致 |
| 资源/用户 | token 节省与摊销模型成本、低频用户冷成本、P50/P95/RSS/离线降级、缓存/任务容量、审阅次数/耗时与误确认 |

**安全 stop：**测试出现跨 owner 泄漏、无同意持久提交/跨会话注入、撤回后的记忆投影复活、暂停后旧记忆块继续发出、数据改变授权、审计不对应 actual view，则不扩大试点。已保留的原文与已发送请求是另外边界，不能伪称已删除。

**效果 go：**相比原始列表与确定性页，模型页在证据支持/冲突时间正确性不退步的前提下，显示可解释的预算/摊销成本或用户收益；阈值根据 A 的实测基线与用途冻结。没有净收益就选择确定性页/现有 M1，而不是继续堆组件。
